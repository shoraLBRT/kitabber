# ADR-0113. Закладки на посты и комментарии: модуль Reactions, автор цели в строке, счётчик только автору

- Статус: принято
- Дата: 2026-11-27
- Задачи: E10-07 (#108); раздел «Закладки» — E04-12 (#109). Опирается на [ADR-0061](0061-likes.md) (ключ «цель,
  аккаунт», цели — пост и комментарий), [ADR-0091](0091-block-menu-items.md) (меню «…» комментария),
  [ADR-0107](0107-comment-link.md) («Скопировать ссылку»)

## Контекст

FR-REACT: «Закладки на посты и комментарии с отдельным разделом». Критерии E10-07: закладка ставится и снимается с
карточки и со страницы, счётчик закладок виден автору. Закладка, в отличие от реакции, — личное: она ни на кого не
влияет и никому не показывается, кроме числа для автора.

## Решение

1. **Модуль — Reactions**, таблица `reactions.bookmarks`. FR-REACT объединяет реакции и закладки, у них одни цели
   (`ReactionTarget`: пост, комментарий) и одни проверки цели через `IPostDirectory` и `ICommentDirectory`. Отдельный
   модуль ради одной таблицы — лишняя схема, миграции и регистрация без выигрыша.
2. **Строка** — `(target_kind, target_id, account_id)` ключом, `post_id`, `target_author_id`, `created_at`. Ключ делает
   повтор ничем, в том числе при гонке (уникальное нарушение глотается). Индекс `(account_id, created_at)` — для раздела
   «Закладки» (E04-12), индекс `post_id` — для страницы поста.
3. **Автор цели хранится в строке.** Он известен при постановке (из `PostSummary`/`CommentSummary`) и не меняется, поэтому
   счётчик для автора считается внутри модуля, без массового запроса авторов к Posts и Comments и без новых контрактов.
   У гостевого комментария автора-аккаунта нет (`null`) — счётчик там никому не показывается.
4. **API** (все маршруты — только с аккаунтом, подтверждённая почта не нужна: закладка никого не касается):
   - `PUT`/`DELETE /api/v1/posts/{postId}/bookmark` и `/api/v1/comments/{id}/bookmark` — поставить и снять; ответ
     `BookmarkView {bookmarked, count}`. Пост — только опубликованный, комментарий — только показанный, иначе 404
     (`bookmarks.post_not_found`, `bookmarks.comment_not_found`). Свой пост, свой и гостевой комментарий в закладки
     ставятся.
   - `GET /api/v1/posts/{postId}/bookmarks` — пост и его комментарии для страницы поста одним запросом.
   - `GET /api/v1/bookmarks/posts?ids=…` — посты карточек ленты одним запросом, не больше 100 (`MaxFeedPosts`);
     неверный идентификатор или больше 100 — 400 с ошибкой поля `ids`.
   - `count` — число людей, у кого цель в закладках, и только для автора цели; остальным `null`. В списках есть лишь
     цели, которые аккаунт держит в закладках или написал и их кто-то держит.
5. **Клиент.** Одно хранилище закладок на всё приложение (`useBookmarks`, `provide` в `app.vue`, ключ `bookmarksKey`):
   закладка, поставленная на странице поста, видна на карточке в ленте без нового чтения; смена аккаунта забывает
   прочитанное. Запросы идут через свой сервер (`/bff/bookmarks`, `/bff/bookmark`) с токеном человека (ADR-0018); гость
   ничего не читает, его нажатие открывает окно входа, и после входа закладка ставится сама (отложенное действие
   `bookmark:<post|comment>:<id>`). Нажатие сразу показывает новое состояние, ответ сервера его заменяет, сбой
   возвращает прежнее с тостом; удача — тост «Добавлено в закладки» / «Убрано из закладок».
   - Кнопка `BookmarkButton` («В закладки», `aria-pressed`) — в панели действий поста между «Комментариями» и
     «Поделиться» и в конце ряда счётчиков карточки ленты; рядом число для автора, если оно больше нуля.
   - У комментария — пункт меню «…» «В закладки» / «Убрать из закладок» после «Скопировать ссылку»; автор видит число
     в подписи пункта («В закладки · 2»). Меню получает хранилище через `inject`, дерево комментариев не меняется.

## Последствия

- Закладки удалённого поста или комментария остаются в таблице; раздел «Закладки» (E04-12) сам решает, как их
  показывать.
- Число для автора на карточке читается один раз за открытие ленты; чужие новые закладки приходят со следующим
  открытием (живого обновления нет).
- На отдельном экране ветки (E09-06) состояние закладок комментариев не читается: пункт показывает «В закладки», а
  нажатие ставит закладку (повтор безвреден).
