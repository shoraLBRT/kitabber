# ADR-0012. Дизайн-токены: `brand/tokens.json`, CSS-переменные и линтер стилей

- Статус: предложено (задача E02-02, #12)
- Задачи: E02-02; пользуются E02-03 (#13), E02-04 (#14), каркасы раскладок (#15, #16), темы оформления (FR-UI)

## Контекст

Нужны токены цветов, типографики и отступов для светлой и тёмной палитры, общие для двух независимых пакетов
pnpm (`frontend/`, `admin/`), и проверка линтером, что компоненты не пишут цвета и размеры напрямую. Цвета бренда
уже лежат в `brand/brand.json` (ADR-0011); второй их копии быть не должно.

## Решение

1. **Источник — два файла данных в `brand/`.** `brand.json` даёт цвета бренда (фон, поверхность, текст,
   второстепенный текст, акцент, текст на акценте); `brand/tokens.json` — остальное: дополнительные роли цветов
   обеих палитр (приглушённая поверхность, границы, наведение на акцент, фокус, ошибка, успех, предупреждение),
   шрифты, кегли, начертания, интерлиньяж, трекинг, отступы (шаг 4 px), скругления, размеры (иконки, знак,
   ширина строки для чтения, колонки раскладки из ТЗ, раздел 5) и границы раскладок 640/925/1240 px.
2. **CSS-переменные генерирует `brand/tokens.ts`** (без зависимостей, как `favicon.ts`): `--color-*`, `--font-*`,
   `--line-height-*`, `--letter-spacing-*`, `--space-*`, `--radius-*`, `--size-*`. Результат закоммичен как
   `brand/tokens.css`; тест `frontend/tests/tokens.spec.ts` сверяет файл с генератором (`toMatchFileSnapshot`),
   после правки JSON файл обновляет `pnpm test -u` в `frontend/`. Сайт подключает файл через `css` в
   `nuxt.config.ts`, админка — импортом в `main.ts`; в образы он попадает вместе с `brand/` (ADR-0011, п. 4).
3. **Темы через атрибут.** `:root` и `[data-theme='light']` — светлая палитра, `[data-theme='dark']` — тёмная;
   без атрибута действует системная тема (`prefers-color-scheme`). Атрибут на любом элементе переключает палитру
   его поддерева — так витрина показывает обе темы рядом. Переключатель темы — задача FR-UI, не эта.
4. **Типографика для лонгридов**: системные шрифты (без загрузки веб-шрифтов), текст статьи — 18 px
   (`--font-size-reading`), интерлиньяж 1,7, ширина строки не больше 40rem (около 70 знаков). Выбор шрифта
   пользователем (FR-UI) позже переопределит `--font-family-*`.
5. **Линтер стилей — stylelint** с `postcss-html` для `.vue`. Правила лежат в `brand/stylelint-rules.mjs` (одни на
   оба приложения), конфиги `stylelint.config.mjs` приложений одинаковы. Запрещены: hex, именованные цвета и
   цветовые функции; единицы длины (`px`, `rem`, `em` …) в отступах, размерах, шрифтах, границах, тенях и
   собственных переменных; числа в `font-weight` и `line-height`; шрифты не через переменную. Разрешены `0`,
   `auto`, проценты, `vw`/`vh`, `currentColor`, ключевые слова и `calc()` из токенов. Медиазапросы пишут числа
   из `breakpoint` (переменные там не работают).
6. **Проверки** (`frontend/tests/tokens.spec.ts`): файл токенов совпадает с генератором; роли цветов одинаковы в
   обеих палитрах; весь текст (основной, второстепенный, акцент, статусы) на фоне, поверхности и приглушённой
   поверхности — не ниже 4,5:1, текст на акценте — 4,5:1, фокус и сильная граница — 3:1 (WCAG 1.4.11);
   типографика для чтения; линтер ловит каждое запрещённое значение и пропускает токены; оба приложения
   запускают линтер; в стилях приложений нет `var(--…)`, которых нет среди токенов.

## Почему так

- Закоммиченный CSS виден людям, редактору и линтеру; генерация в тесте не требует отдельного шага сборки или
  исполнителя TypeScript, а рассинхрон ловит CI.
- Отдельный `tokens.json` оставляет `brand.json` описанием бренда, который сменится в M5, а токены — системой,
  которая переживёт смену бренда.
- Встроенных правил stylelint хватает; плагины вроде `stylelint-declaration-strict-value` добавили бы зависимость
  без новой возможности.

## Последствия

- Новый цвет или размер сначала появляется в `tokens.json` (и в тесте контраста, если это цвет текста).
- `BrandLogo` больше не берёт hex из `brand.json`: он красится переменными и следует теме страницы, а проп
  `theme` закрепляет палитру атрибутом `data-theme`. Значок вкладки по-прежнему строится из `brand.json`.
- Линтер не видит значения в привязках `:style` шаблонов; витрины используют их только для показа самих токенов.
