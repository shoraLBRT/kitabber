# ADR-0069. Телеметрия стенда stage: коллектор OpenTelemetry, Prometheus, Loki, Tempo и Grafana отдельными контейнерами

- Статус: предложено (26 ноября 2026), задача E01-xx (#318); действует, пока владелец не решит иначе
- Связанные решения: [ADR-0015](0015-observability.md) (OTLP, `/metrics`, JSON-логи), [ADR-0010](0010-images-and-deployment.md)
  (stage на Docker Compose, выкладка по SSH), ADR-0007 (секреты только из окружения)

## Контекст

API и воркеры отдают трассы, метрики и логи по OTLP (ADR-0015), но на стенде их никто не принимал. Владелец выбрал
Grafana-стек. Задача допускает и один контейнер `grafana/otel-lgtm`. Выкладка управляет Docker сервера по SSH и
ничего не копирует на сервер (ADR-0010), поэтому файлы конфигурации рядом с compose-файлом на сервере не
существуют.

## Решение

1. **Отдельные контейнеры** в `deploy/compose.stage.yaml`: `otel-collector` (сборка contrib), `prometheus`, `loki`,
   `tempo`, `grafana`. Каждый образ закреплён по тегу и дайджесту, Renovate обновляет их, как остальные образы
   compose-файла.
2. **Поток данных.** Хосты бэкенда получают `OTEL_EXPORTER_OTLP_ENDPOINT=http://otel-collector:4317`. Коллектор отдаёт
   трассы в Tempo (OTLP/gRPC), логи в Loki (его родной приём OTLP, `trace_id` — структурные метаданные), метрики в
   Prometheus (приёмник OTLP, `--web.enable-otlp-receiver`; `job` — имя сервиса). `/metrics` API Prometheus снимает
   внутри сети отдельным заданием `platform-api-scrape` — проверка, что точка жива; дашборды и алерт читают OTLP.
3. **Закрыто снаружи.** Портов не публикует никто, кроме Caddy; Caddy отдаёт только Grafana на `GRAFANA_ADDRESS`.
   В Grafana — только администратор с паролем `GRAFANA_ADMIN_PASSWORD` (секрет окружения `stage`), анонимного входа
   и регистрации нет, отчёты и проверки обновлений выключены.
4. **Хранение — 14 дней** везде: Prometheus `--storage.tsdb.retention.time=14d` (и не больше 10 ГБ), Loki
   `retention_period: 336h` с удалением компактором, Tempo `block_retention: 336h`. Вывод контейнеров в docker
   ограничен 5 × 20 МБ.
5. **Конфигурация — код внутри compose-файла** (`configs:` с `content`, как Caddyfile): так она доходит до удалённого
   Docker без копирования файлов. Источники данных и три дашборда («API», «.NET runtime», «PostgreSQL (Npgsql)»)
   Grafana берёт из provisioning, правки в интерфейсе не сохраняются. Из строки лога — переход к трассе, из спана —
   к логам трассы. Дашборд базы принимает обе схемы имён метрик Npgsql (старую `db.client.connections.*` и
   соглашения OpenTelemetry `db.client.connection.*`).
6. **Журнал запросов API на стенде**: `Microsoft.AspNetCore.Hosting.Diagnostics` на `Information` — строка на запрос
   с trace id, чтобы от запроса можно было найти и лог, и трассу. Строки проб и `/metrics` коллектор отбрасывает.
7. **Алерт на 5xx** — правило Prometheus `ApiServerErrors` (доля 5xx больше 5% пять минут). Канала оповещений нет:
   его выбирает владелец (Telegram или почта), подключение — отдельная задача.
8. **Проверка без сервера.** `scripts/deploy-test.ps1` статически проверяет пункты 2–5; смоук в `images / build`
   поднимает стек и через Grafana находит трассу, строку лога и метрику запроса к API.

## Последствия

- На сервере стенда нужно ещё около 1 ГБ памяти и до 20 ГБ диска; третья запись DNS — для Grafana.
- Пароль Grafana действует с первого запуска: Grafana берёт переменную, только когда создаёт администратора. Смена —
  `grafana cli admin reset-admin-password` (docs/DEPLOY.md).
- Метрики API приходят дважды (OTLP и снятие `/metrics`) под разными `job`; запросы дашбордов фильтруют по `job`.
- Nuxt пока не шлёт телеметрию (ADR-0015); коллектор уже принимает OTLP/HTTP на 4318.
- Production — вне решения: владелец выбирает отдельный сервер с тем же составом или Grafana Cloud до открытой беты;
  код при этом не меняется, меняется адрес коллектора или его экспортёры.

## Рассмотренные варианты

- **Один контейнер `grafana/otel-lgtm`.** Меньше конфигурации, но это образ для разработки: срок хранения и
  ресурсы каждого хранилища не настраиваются явно, все компоненты обновляются одной версией, а смена одного из них
  (например, Tempo на Grafana Cloud) требует разобрать образ.
- **Grafana Alloy вместо коллектора.** Равноценен по задаче; коллектор OpenTelemetry — тот же протокол и
  поставщик-нейтральная конфигурация, о которой говорит ADR-0015.
- **Файлы конфигурации рядом с compose-файлом.** На удалённом Docker их нет; копировать файлы на сервер выкладка
  не умеет и по ADR-0010 не должна.
