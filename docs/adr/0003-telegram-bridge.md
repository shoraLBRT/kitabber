# ADR-0003. Мост с Telegram: отдельный шлюз, бот для новых постов, MTProto для истории

- Статус: предложено (19 ноября 2026); предположения проверяет задача E19-01
- Требования: [telegram-bridge.md](../telegram-bridge.md)
- Задачи: эпик E19

## Контекст

Нужно переносить историю канала, ретранслировать новые посты и показывать комментарии из Telegram. Telegram в
России заблокирован, а серверы платформы находятся в России.

## Решение

1. **Отдельный сервис-шлюз.** Весь обмен с Telegram делает сервис `Telegram.Gateway`, который можно
   разместить за пределами России. С ядром он общается только через очередь сообщений и хранилище медиа.
   Ядро знает интерфейс `ITelegramGateway` и ничего не знает о протоколах Telegram.
2. **Бот — для новых событий и подтверждения владения.** Автор добавляет бота администратором канала и в
   группу обсуждения. Бот получает новые посты, правки и комментарии, публикует анонсы.
3. **Клиент MTProto — для истории.** Bot API не отдаёт прошлые сообщения, поэтому импорт истории и старых
   комментариев выполняет клиент MTProto под служебным аккаунтом платформы (для .NET — библиотека
   WTelegramClient). Работает для публичных каналов; для закрытых — только если автор добавит служебный
   аккаунт в канал.
4. **Архив экспорта — запасной путь.** Автор выгружает канал из Telegram Desktop и загружает архив. Работает
   всегда, без доступа платформы к Telegram.
5. **Данные.** Пост и комментарий получают происхождение (`origin`) и ссылку на внешний источник; уникальный
   ключ «канал + сообщение» делает обработку идемпотентной. Гостевой комментарий — тот же комментарий с
   видом `guest` и внешним автором вместо `account_id`. Эти поля закладываются в моделях уже в M1 (E07-01,
   E09-01), чтобы не переделывать схему в M6.
6. **Медиа** скачивает шлюз и кладёт в хранилище платформы.

## Последствия

- Плюс: ядро тестируется без Telegram на фейковом шлюзе.
- Плюс: блокировка Telegram не мешает платформе; при недоступности шлюза страдает только синхронизация.
- Минус: нужен сервер вне России и служебный аккаунт Telegram — это задачи владельца.
- Риск: служебный аккаунт MTProto могут ограничить за массовое чтение; поэтому импорт идёт с паузами, а
  архив экспорта остаётся запасным путём.
- Риск: правки и удаления доходят не всегда; синхронизация заявлена как «по возможности».

## Что нужно от владельца (до начала M6)

- Бот в Telegram (токен), служебный аккаунт и `api_id`/`api_hash` для MTProto.
- Сервер или контейнерный хостинг вне России для шлюза.
- Тестовый канал с группой обсуждения.

## Рассмотренные варианты

- **Только бот.** Не может импортировать историю — не выполняет главное требование.
- **Только MTProto.** Может всё, но автор не подтверждает владение естественным способом, и вся нагрузка
  ложится на служебный аккаунт.
- **Разбор публичной веб-версии канала.** Хрупко и не даёт комментариев.
