# ADR-0124. Страница результатов поиска: блоки, фильтры постов, «Подписаться» в строках

Статус: предложено (задача E14-03, #117).

## Контекст

FR-SEARCH: поиск открывается внутри раздела «Рейтинг» — поле запроса с «Отмена», ниже блоки «Блоги», «Темы» и «Посты»
с кнопкой «Подписаться» в строках и «Показать ещё»; кнопка фильтров у блока «Посты». Критерии E14-03: блоки с
«Подписаться», фильтры «только заголовки», период, порядок; пустой результат — заглушка. Индексы ведёт модуль Search
(ADR-0094), подсказки шапки читают их через API (ADR-0097). Раздела «Рейтинг» ещё нет (E14-04).

## Решение

1. **Адрес.** Результаты живут на `/rating?q=<запрос>`; фильтры постов — в том же адресе: `titles=1`,
   `period=day|week|month|year`, `order=date` (значения по умолчанию не пишутся). Enter в поиске шапки без выбранной
   подсказки записывает запрос в историю и открывает этот адрес. Без `q` страница пока показывает поле и приглашение
   ввести запрос; топ блогов, темы и рекомендованные посты раздела добавят E14-04…E14-06.
2. **API — блок за блоком, по смещению.** Два эндпоинта модуля Search:
   `GET /api/v1/search/blogs?q=&kind=personal|topic&offset=` (страница 5 строк) и
   `GET /api/v1/search/posts?q=&titlesOnly=&period=all|day|week|month|year&order=relevance|date&offset=`
   (страница 10 строк). Ответ `{ items, hasMore }`; «Показать ещё» блока читает следующую страницу только этого блока,
   смена фильтров перечитывает только «Посты». Смещение, а не курсор: порядок по релевантности не даёт устойчивого
   ключа, а глубже 500 результатов (`MaxOffset`) никто не листает. Неизвестный `kind`, `period`, `order`, смещение вне
   0…500 и пустой или длинный запрос — `400 validation_failed` по своему полю. Лимит частоты — тот же
   `search.suggestions` (ADR-0097).
3. **Фильтры — в движке.** `ISearchIndex.FindAsync(index, SearchQuery)`: `multi_match` с `operator: and`, для
   «только заголовков» — по полю `title`; период — фильтр `range` по `publishedAt` от «сейчас минус сутки, 7 дней,
   месяц, год» по `TimeProvider`; порядок по дате — `sort` по `publishedAt` по убыванию; вид блога — `term` по `kind`.
   Фильтры стоят в `filter`/`must_not` и не меняют релевантность. Фейк `InMemorySearchIndex` повторяет те же правила
   без морфологии.
4. **Чёрный список — тоже в движке.** Посты и личные блоги аккаунтов из чёрного списка читателя (ADR-0091) исключаются
   через `must_not`, а не отбрасываются после поиска: иначе страницы по смещению выходили бы короче и с дырами. Темы не
   скрываются, как в подсказках.
5. **Строки блогов — как в списках подписок.** Строка блога или темы — `{ id, type, name, nickname, avatarSources,
   subscribed, own }`, та же форма, что у строки списка подписчиков (ADR-0099), и показывается тем же компонентом
   `SubscriptionList` с «Подписаться» / «Вы подписаны»; у своего личного блога кнопки нет. Отметки «подписан» модуль
   Search берёт одним запросом через новый контракт `IBlogSubscriptions.SubscribedAmongAsync`; названия и аватары — через
   `IBlogDirectory.CardsAsync`, как в подсказках. Нажатие идёт через тот же `/bff/subscription`
   (`useRowSubscriptions`, общий со списками подписчиков); гостю — окно входа.
6. **Строка поста** — `{ id, blogId, title, excerpt, publishedAt, blog }`, где `blog` — карточка блога или темы поста
   (или `null`, если блога больше нет); ведёт на `/u/<blogId>/<id>`.
7. **Интерфейс.** Сайт читает блоки в браузере через BFF `/bff/search-blogs` и `/bff/search-posts` (ответы зависят от
   подписок и чёрного списка читателя, токен остаётся на сервере, ADR-0018). Блок, который ничего не нашёл, не
   показывается; «Посты» остаются, пока включён фильтр, чтобы его можно было снять. Если не нашлось ничего и фильтры по
   умолчанию — заглушка «По запросу «…» ничего не нашлось». Состояния: скелетоны во время поиска, ошибка с «Повторить».
   Кнопка «Фильтры» у «Постов» раскрывает «Только заголовки», период и порядок; с фильтром в адресе панель открыта
   сразу. «Отмена» у поля уходит на `/rating` без запроса.

## Последствия

- Контракт `IBlogSubscriptions` растёт на один метод; модуль Search по-прежнему не читает чужих таблиц.
- Предложения, ждут подтверждения владельца: размеры страниц (5 блогов или тем, 10 постов), предел смещения 500,
  периоды «сутки, неделя, месяц, год», общий лимит частоты с подсказками, страница результатов на `/rating` до
  появления самого раздела.
- Фильтры ТЗ «точное совпадение», «посты редакции» и «автор» в критерии E14-03 не входят и не сделаны: для «редакции»
  нет понятия в модели, для «автора» нужен выбор автора; это отдельные задачи.
