# ADR-0014. Типизированный клиент API: openapi-typescript и openapi-fetch в каждом клиенте

- Статус: принято владельцем 20 ноября 2026 (задача E01-08, #19)
- Задачи: E01-08; опирается на [ADR-0001](0001-stack.md) и [ADR-0006](0006-rest-api-conventions.md) (снимок OpenAPI)

## Контекст

Сайт (`frontend/`, Nuxt) и админка (`admin/`, Vue + Vite) обращаются к API. Типы запросов и ответов не должны
писаться руками, а расхождение клиента и API должно ронять `ci / verify`. Описание API — снимок
`backend/src/Api/openapi/v1.json` (ADR-0006); его совпадение с кодом бэкенда уже проверяет `OpenApiSnapshotTests`.
`docs/ARCHITECTURE.md` резервировал под генерацию клиента каталог `tools/`.

## Решение

1. **Генератор — `openapi-typescript` (MIT), клиент — `openapi-fetch` (MIT).** Генерируются только типы
   (`schema.d.ts`: `paths`, `components`); рантайм — обёртка над `fetch` размером в несколько килобайт, которая
   выводит типы параметров, тела, ответа и ошибки по пути и методу. Генераторы с кодом на каждый метод
   (`openapi-generator`, `orval`) отклонены: больше кода в диффе, Java или своя конфигурация, а пользы для двух
   клиентов на `fetch` нет.
2. **Клиент лежит в каждом приложении:** `frontend/api/` и `admin/src/api/` — `schema.d.ts` (сгенерирован,
   закоммичен, вне Prettier) и `client.ts` (`createApiClient(options)`). Общий пакет вне приложений отклонён: у
   сайта и админки отдельные `pnpm`-проекты и образы, а импорт пакета `openapi-fetch` из каталога вне приложения не
   разрешается без третьей установки зависимостей. Цена — два одинаковых файла по десятку строк. Каталог `tools/`
   для генерации не нужен.
3. **Команда пересборки:** `pnpm run api:generate` в `frontend/` или `admin/`. Изменил API — обнови снимок
   (`UPDATE_OPENAPI_SNAPSHOT=1`), затем выполни команду в обоих клиентах и закоммить всё вместе.
4. **Проверка в CI:** `tests/api-client.spec.ts` каждого клиента запускает ту же команду из `package.json` во
   временный файл и сравнивает с закоммиченным `schema.d.ts`. Цепочка: код бэкенда → снимок
   (`OpenApiSnapshotTests`) → клиент (Vitest); оба теста идут в `scripts/verify.ps1`.
5. **Ручных обращений к API нет:** тот же тест падает, если в исходниках клиента вне `api/` встречается строка
   `/api/…`, `fetch(`, `$fetch`, `useFetch` или `useLazyFetch`. Ответы и ошибки берут типы только из `schema.d.ts`.
6. Пути в схеме уже начинаются с `/api/v1`, поэтому `baseUrl` клиента — адрес хоста API (пусто — тот же хост).
   Откуда сайт берёт адрес API при отрисовке на сервере, решает первая задача с данными (переменная окружения
   через `runtimeConfig`).

## Последствия

- Изменение API без пересборки клиента ловится тестом; изменение клиента видно в диффе PR рядом со снимком.
- Пока у API нет эндпоинтов, `paths` пуст, и типизированные вызовы появятся с первым модулем.
- Обновления `openapi-typescript` и `openapi-fetch` приходят от Renovate; смена формата вывода генератора
  потребует перегенерировать файлы в том же PR.
