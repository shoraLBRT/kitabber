# ADR-0102. Онбординг после регистрации: признак в личном блоге, один запрос в конце, переход из колбэка входа

- Статус: принято (длина имени и шаг уведомлений — предложения, требуют подтверждения владельца)
- Дата: 2026-11-27
- Задачи: E03-10 (#93); опирается на [ADR-0025](0025-blogs-subsite-and-profile.md) (личный блог и правила профиля),
  [ADR-0034](0034-profile-editing-and-avatar.md) (аватар через медиасервис), [ADR-0085](0085-blog-subscriptions.md)
  (подписки), [ADR-0088](0088-topic-menu-and-catalog.md) (каталог тем), [ADR-0018](0018-openid-connect-provider.md) (вход и BFF)

## Контекст

FR-AUTH: «Онбординг после регистрации: имя (2–30 символов), аватар, выбор тем, включение уведомлений; каждый шаг можно
пропустить». Критерии E03-10: имя проверяется, выбранные темы становятся подписками, пропуск шага не блокирует вход,
онбординг не показывается повторно. Имя, аватар и подписки уже живут в модуле Blogs (личный блог, ADR-0025); настроек
уведомлений ещё нет (E12-05, #202).

## Решение

1. **Признак — в личном блоге.** У `blogs.subsites` новый столбец `onboarded_at` (`Subsite.OnboardedAt`): `null` —
   онбординг впереди. Миграция `AddOnboarding` проставляет всем уже существующим личным блогам время их создания,
   демо-блоги сидера создаются пройденными: онбординг видят только новые аккаунты. Блог создают воркеры по
   `account.created.v1` или `GET /profiles/me` (ADR-0025), поэтому признак есть с первого входа, без гонки с очередью.
   Отдельной таблицы в Preferences нет: всё, что меняет онбординг, принадлежит Blogs.
2. **API.** Профиль владельца отдаёт `onboardingPending` (`true` только своему личному блогу, остальным всегда `false`).
   `POST /api/v1/profiles/me/onboarding` с `{ name?, avatarId?, topicIds? }` сохраняет всё разом и отмечает онбординг
   пройденным; пустое или отсутствующее поле — пропущенный шаг, он ничего не меняет. Пустой запрос только отмечает
   пройденным. Повторный запрос — 409 `blogs.onboarding_done`, ничего не меняет. Ошибки полей — 400 `validation_failed`
   по полям `name`, `avatarId` (чужой файл, не картинка — как в E04-03), `topicIds` (не тема, неизвестный id, больше 50).
   Новые подписки публикуют `BlogSubscribed`, как `PUT /blogs/{id}/subscription`; уже существующая остаётся.
3. **Длина имени — от 2 до 25 символов** (графемы, пробелы по краям не считаются; `SubsiteRules.IsValidOnboardingName`).
   ТЗ называет 2–30, но онбординг заполняет то же название блога, что и настройки (FR-PROFILE: до 25); имя из 26–30
   символов настройки потом не дали бы сохранить. **Предложение, требует подтверждения:** либо оставить 25, либо поднять
   предел названия блога до 30 везде.
4. **Сайт.** Колбэк входа (`server/routes/auth/callback.get.ts`) после создания сессии спрашивает свой профиль и, если
   `onboardingPending`, ведёт на `/onboarding?returnTo=<куда шёл человек>`; если API не ответил — сразу на страницу,
   вход онбординг не блокирует. Страница `/onboarding` (`pages/onboarding.vue`, `components/onboarding/OnboardingSteps.vue`)
   — три шага в одной карточке: «Как вас зовут?» (поле «Имя» со счётчиком, проверка 2–25 до отправки), «Аватар»
   (загрузка с кадрированием, как в настройках блога), «Выберите темы» (первая страница каталога, самые популярные,
   плитки-переключатели с `aria-pressed`). У каждого шага «Пропустить» (сбрасывает выбор шага), «Далее»/«Готово» и
   «Назад». Аватар загружается через медиасервис только в конце, затем один запрос в API через `/bff/onboarding`.
   Ошибка поля возвращает к своему шагу, сбой — тост, выбор сохраняется. Уже пройденный онбординг (другая вкладка,
   старая ссылка) страница не показывает и ведёт на `returnTo`; `returnTo` — только локальный путь. Адрес `onboarding`
   добавлен в зарезервированные (`TopicCreationRules.ReservedAddresses`): ни тема, ни никнейм его не займут.
   Состояния: загрузка профиля — скелет; профиль не загрузился — «Повторить» и «Пропустить»; темы грузятся —
   «Загрузка»; темы не загрузились — «Повторить»; тем нет — текст про каталог. На 390 px кнопки шага делят ширину.
5. **Уведомления — не сейчас.** Шага «включение уведомлений» нет: настроек уведомлений по типам и каналам и браузерных
   push ещё нет (E12-05, #202; PWA). Когда они появятся, шаг добавляется четвёртым в `OnboardingSteps.vue` и полем в
   `OnboardingInput`; признак `onboarded_at` уже пройденным аккаунтам его не покажет — **предложение:** предложить
   включение уведомлений отдельной плашкой, а не повторным онбордингом.

## Последствия

- E03-10 закрыт не полностью: остаётся шаг уведомлений (после E12-05) и подтверждение длины имени.
- Аккаунты, подтверждённые до появления блогов и получающие блог через `GET /profiles/me`, увидят онбординг при
  следующем входе — на стенде таких единицы, это безвредно.
- Другие способы входа (внешние провайдеры) проходят тот же колбэк и получают онбординг без доработок.
