# ADR-0017. Почта: шаблоны в файлах, отправка через очередь воркеров, SMTP за интерфейсом

- Статус: принято владельцем 20 ноября 2026 (задача E01-12, #22)
- Задачи: E01-12; опирается на [ADR-0001](0001-stack.md) (внешний сервис за интерфейсом с фейком),
  [ADR-0005](0005-messaging-and-cache.md) (шина и повторы), [ADR-0007](0007-configuration-and-secrets.md)
  (настройки), [ADR-0011](0011-brand-source-and-icons.md) (название продукта в одном месте)

## Контекст

ТЗ (раздел 7) отдаёт почту воркерам на очереди. Письма нужны входу по коду, смене почты, восстановлению доступа и
уведомлениям (раздел 4). Задача E01-12: отправка через SMTP с шаблонами и очередью, повтор при ошибке, локализуемые
шаблоны со снимками, тесты читают письмо из Mailpit, боевой SMTP — из настроек. Почтового сервиса у проекта пока
нет: его выбирает владелец, платный провайдер без него не подключаем.

## Решение

1. **Библиотека `Platform.Mail`** (`backend/src/Mail`). Сообщение шины `SendEmail` несёт уже готовое письмо: id,
   имя шаблона, адрес, тему, текст и HTML.
2. **`IMailer.SendAsync(адрес, шаблон, культура, значения)`** рендерит письмо сразу и публикует `SendEmail`. Неверный
   адрес, неизвестный шаблон или незаполненное поле падают у вызывающего, а не в очереди; внутри транзакции
   модуля сообщение уходит через его outbox (ADR-0005). Хост, который шлёт почту, подключает `AddPlatformMail()` и
   шину.
3. **Доставка — в воркерах**: `SendEmailConsumer` отдаёт письмо `IEmailSender`. Ошибка доставки — исключение; шина
   повторяет сообщение (100, 500 и 1000 мс, ADR-0005), затем кладёт его в очередь `send-email_error`, откуда его
   можно вернуть, когда почта заработает. Повтор — то же письмо: `Message-ID` строится из id.
4. **`IEmailSender`**: `SmtpEmailSender` на MailKit (MIT) — любой SMTP-сервер по настройкам `Mail:Smtp:*` и
   `Mail:From:*` ([CONFIG.md](../CONFIG.md)); фейк `InMemoryEmailSender` (`Mail:Provider=InMemory`) — для тестов.
   Локально и в интеграционных тестах SMTP — Mailpit (`compose.yaml`; в тестах — тот же образ в Testcontainers,
   письмо читается через его API, `MailpitClient`). Отдельного API провайдера (HTTP) нет: SMTP дают все сервисы.
5. **Шаблоны** — файлы `backend/src/Mail/Templates/<культура>/`, встроенные в сборку: `<имя>.subject.txt`,
   `<имя>.txt`, `<имя>.html`, общий макет `_layout.txt` и `_layout.html` с `{{content}}`. Поля — `{{имя}}`, в HTML
   экранируются; встроенные — `{{product}}`, `{{subject}}`, `{{color.<роль>}}`. Поле без значения — ошибка.
   Культура ищется так: запрошенная, её родитель, затем русский (`ru`), в котором есть каждый шаблон. Новый язык —
   папка с теми же файлами.
6. **Название продукта и цвета** берутся из `brand/brand.json`, встроенного в сборку при компиляции (Dockerfile
   копирует этот файл). В шаблонах названия нет — это проверяет тест. Имя отправителя по умолчанию — то же
   название.
7. **Снимки**: тест рендерит каждый шаблон каждой культуры с образцовыми значениями и фиксированным брендом и
   сравнивает с `backend/tests/Platform.Mail.Tests/Snapshots/<шаблон>.<культура>.snap`. Обновление —
   `UPDATE_SNAPSHOTS=1 dotnet test`; в CI отсутствующий снимок — ошибка.

## Почему так

- Рендер у отправителя, а не в воркере: ошибка шаблона видна сразу и не повторяется в очереди впустую; воркеру не
  нужны данные модулей.
- Свои шаблоны с `{{поле}}`, а не Razor, Scriban или Fluid: писем немного, логики в них нет, а зависимость и
  второй язык шаблонов не нужны. Если появятся циклы и условия (дайджест «Интересное за день»), шаблонизатор можно
  заменить за `MailTemplateRenderer`, не трогая отправителей.
- SMTP, а не HTTP API провайдера: работает с любым сервисом и с Mailpit одинаково, выбор провайдера остаётся за
  владельцем и не меняет код.
- MailKit, а не `System.Net.Mail.SmtpClient`: Microsoft сам не рекомендует его для новой разработки.

## Последствия

- Задачи модулей (вход по коду E03, уведомления) добавляют свои шаблоны и образцы значений в
  `TemplateTests.Samples`; снимок пишется тестом.
- API шину ещё не подключает: первая задача, которой нужна почта из API, подключает `AddPlatformMessaging` и
  `AddPlatformMail` (outbox модуля — ADR-0005).
- Повтор короткий (меньше двух секунд): долгий сбой почтового сервиса оставит письма в `send-email_error`. Отложенные
  повторы (минуты) требуют планировщика сообщений — отдельная задача, если сбои начнут случаться.
- Одно SMTP-соединение на письмо: достаточно, пока писем мало; массовые рассылки потребуют пула соединений.
- Для стенда владелец даёт почтовый сервис, домен отправителя и записи SPF, DKIM, DMARC
  ([DEPLOY.md](../DEPLOY.md#что-нужно-от-владельца)); до этого письма на stage не уходят, но воркеры работают.
