# ADR-0001. Стек: модульный монолит на ASP.NET Core и клиент на Nuxt 3

- Статус: принято владельцем 19 ноября 2026
- Задачи: эпик E01

## Решение

| Часть | Технология |
| --- | --- |
| Сервер | ASP.NET Core, модульный монолит; отдельный хост фоновых воркеров |
| Веб-клиент | Nuxt 3 (Vue 3, TypeScript), серверный рендеринг, PWA |
| Админ-панель | Отдельное приложение на Vue 3 |
| Данные | PostgreSQL (схема на модуль, блоки поста в JSONB), Redis, RabbitMQ (MassTransit, outbox) |
| Поиск | OpenSearch |
| Медиа | S3-совместимое хранилище, imgproxy, FFmpeg-воркер |
| Аналитика | ClickHouse |
| Реальное время | SignalR |
| Доставка | Docker, Compose на старте, GitHub Actions |

## Модули

`Identity`, `Blogs`, `Posts`, `Editor` (схемы блоков), `Media`, `Comments`, `Reactions`, `Feeds`, `Topics`,
`Notifications`, `Messaging`, `Search`, `Moderation`, `Stats`, `Telegram`.

Правила границ:

- у модуля своя схема базы и свой `DbContext`;
- модули общаются через публичные контракты (`*.Contracts`) и события шины, а не через чужие таблицы;
- внешние сервисы (почта, хранилище, капча, Telegram, классификаторы, ИИ) скрыты за интерфейсами и имеют
  фейковые реализации для тестов;
- время берётся из `TimeProvider`, случайность — из внедряемого источника.

Границы проверяются архитектурными тестами (E01-18).

## Почему так

- Одна выкладка и одна база на старте проще в эксплуатации для маленькой команды и для автономной
  разработки сессиями.
- Чёткие модули позволяют позже вынести `Identity` (ADR-0002) и `Telegram` (ADR-0003) в отдельные сервисы.
- Nuxt даёт серверный рендеринг, нужный текстовой платформе для поиска и скорости первого экрана.
