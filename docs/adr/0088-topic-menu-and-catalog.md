# ADR-0088. Темы в меню и каталог тем

- Статус: предложено 26 ноября 2026, задача E11-02 (#78)
- Требования: [spec.md](../spec.md) (FR-TOPIC; FR-SUB; раздел 5: «список тем с „Показать все“» в левом меню),
  [docs/ui/README.md](../ui/README.md) (экран «Меню» повторяет левую колонку)
- Связанные решения: [ADR-0006](0006-rest-api-conventions.md) (курсорная пагинация), [ADR-0018](0018-openid-connect-provider.md)
  (токен остаётся на сервере сайта), [ADR-0046](0046-publishing-checks.md) (список тем редактора),
  [ADR-0082](0082-topic-owner-and-topic-page.md) (страница темы), [ADR-0084](0084-topic-creation-by-people.md)
  (создание тем), [ADR-0085](0085-blog-subscriptions.md) (подписки и их числа)

## Контекст

В левом меню и на экране «Меню» был блок «Темы» с пустым списком и ссылкой «Показать все» на несуществующий
`/topics`. Задача: в меню — темы человека или популярные для гостя, каталог ищется и сортируется по подписчикам.
Список редактора `GET /api/v1/topics` (ADR-0046) — все темы по названию без чисел, и менять его форму нельзя: им
пользуется редактор.

## Решение

1. **Два новых чтения в модуле Blogs, открытые всем.**
   - `GET /api/v1/topics/menu` → `TopicMenu { source, topics: TopicSummary[] }`. Вошедшему — темы, на которые он
     подписан, по названию (`source = subscriptions`). Гостю и человеку, который ещё ни на одну тему не подписан, —
     самые популярные темы (`source = popular`), чтобы меню не было пустым. Не больше 10 (`TopicCatalogRules.MenuSize`):
     остальное — в каталоге.
   - `GET /api/v1/topics/catalog?q=&cursor=&limit=` → `CursorPage<TopicCard>` (`id`, `name`, `nickname`,
     `description`, `subscriberCount`). Порядок — по числу подписчиков по убыванию, при равенстве новее выше; курсор —
     `(subscriberCount, id)` по ADR-0006. `q` — подстрока названия или адреса без учёта регистра (`ILIKE` с
     экранированными `%`, `_` и `\`), пробелы по краям и повторные внутри убираются, длиннее 50 символов — 400.
2. **Числа считаются по строкам подписок** подзапросом `count(*)` по индексу `ix_subscriptions_subsite`, как в
   профиле (ADR-0085). Хранимого счётчика нет: тем немного, а число в каталоге всегда точное. Курсор по живому числу
   может пропустить или повторить тему, если её число изменилось между страницами; клиент убирает повторы. Когда тем
   станут тысячи, добавим хранимый счётчик в `subsites` и индекс по `(subscriber_count, id)`.
3. **Клиент.** Меню берёт темы через сервер сайта (`/bff/topic-menu`, ADR-0018) уже в браузере, после показа
   страницы: отрисовка страницы не ждёт меню, а пока темы грузятся или при сбое в меню остаётся «Показать все».
   Список запрашивается снова при входе и выходе и после смены подписки. Каталог `/topics` публичный: первая страница
   рисуется на сервере, следующие и поиск браузер просит у API напрямую; поиск ждёт паузу 300 мс и сохраняется в
   адресе `?q=`. Адрес `topics` уже зарезервирован для тем (ADR-0084).
4. **Баннер cookie на телефоне** закрывал конец длинной страницы — служебные ссылки экрана «Меню», который стал выше
   из-за тем. Под баннером ниже 925 px теперь есть невидимое место его высоты, и конец страницы прокручивается из-под
   него.

## Последствия

- Меню и каталог готовы для «Подписок» (FR-SUB) и скрытия тем: исключать скрытые темы — фильтр в тех же запросах.
- Аватаров тем в меню и каталоге нет: у тем их пока не задают (управление темой — #114).
- Ручного порядка тем в меню и счётчика подписчиков в меню нет; если владелец захочет их, это новая задача.
