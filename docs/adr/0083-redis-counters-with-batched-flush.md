# ADR-0083. Счётчики в Redis со сбросом в базу: буфер записи, пакетный идемпотентный сброс

- Статус: предложено (26 ноября 2026), задача E10-09 (#75); действует, пока владелец не решит иначе
- Требования: [spec.md](../spec.md#fr-react-реакции-закладки-репосты-карма) (FR-REACT), раздел 9 ТЗ (счётчики в
  Redis)
- Связанные решения: [ADR-0005](0005-messaging-and-cache.md) (Redis, `Cache:Provider`),
  [ADR-0071](0071-post-view-counting.md) (учёт просмотров), [ADR-0072](0072-reaction-row-and-live-counts.md) (живые
  счётчики реакций), [ADR-0081](0081-post-and-comment-rating.md) (рейтинг)

## Контекст

По ADR-0071 каждое открытие поста и каждый показ карточки — запись в базу: строка `posts.post_views` и `UPDATE` строки
поста. Строка популярного поста становится горячей: все открытия ждут одну блокировку. ТЗ отводит быстрые счётчики
Redis. Задача: счётчик не теряется при перезапуске, сброс в базу пакетный и идемпотентный.

## Решение

1. **Буфер записи — общий примитив `IWriteBuffer`** в `Platform.Caching`, с тем же `Cache:Provider`, что кэш и
   `IRateCounter`: Redis в бою, память — фейк для тестов. Модули знают только интерфейс.
   - `AppendOnceAsync(buffer, once, lifetime, entry)` — один атомарный скрипт: ставит метку `once` (`SET NX PX`) и
     только для новой метки дописывает запись в список ожидающих.
   - `ClaimAsync(buffer, lease)` — сначала отдаёт пакет, у которого истекла аренда (его взявший остановился), иначе
     переименовывает список ожидающих в новый пакет и записывает аренду в отсортированное множество.
   - `CompleteAsync(batch)` — удаляет применённый пакет.
   - Ключи `platform:buffer:{имя}:…`; фигурные скобки держат все ключи буфера в одном слоте кластера.
2. **Записи живут в Redis, а не в процессе.** Перезапуск любого числа экземпляров API ничего не теряет: что не
   сброшено, сбросит следующий экземпляр. Пакет применяется хотя бы раз: экземпляр, упавший между взятием и
   завершением, оставляет пакет, и после аренды (1 минута) его берёт другой.
3. **Просмотры (модуль Posts).** `BufferedViewCounter` заменил `DatabaseViewCounter`. Открытие и показ — одна операция
   `AppendOnceAsync` с меткой «вид, сутки, пост, зритель» (живёт двое суток) и записью
   `вид|пост|аккаунт|сутки|время|зритель`; время чтения — `AppendAsync`. Секрет суток для гостей по-прежнему в
   `posts.view_salts`.
4. **Сброс идемпотентен в базе, а не только в Redis.** `ViewFlusher` применяет пакет двумя операторами: просмотры —
   `INSERT … ON CONFLICT DO NOTHING` в `post_views` (по ключу пост, вид, зритель, сутки), и счётчики поста растут
   ровно на число вставленных строк в том же операторе; время чтения — `GREATEST`. Повтор пакета (или его части)
   ничего не меняет, поэтому дубли не страшны, даже если метка в Redis пропала. Правила ADR-0071 проверяются при
   сбросе: учитывается только опубликованный и не удалённый пост, свои просмотры автор не накручивает.
5. **Пакетно.** `ViewFlushService` сбрасывает буфер каждые `Posts:Views:FlushSeconds` (5 с по умолчанию) и ещё раз при
   остановке хоста; за один сброс — не больше 20 пакетов, оператор — не больше 2000 записей. `0` выключает сброс на
   экземпляре (он только пишет в буфер). Ошибка сброса пишется в журнал, пакет остаётся и берётся снова после аренды.
   Нечитаемая запись пропускается с предупреждением, чтобы один битый элемент не держал пакет.
6. **Чтение — из базы.** `viewCount` в посте и карточке отстаёт от просмотров на один сброс (до ~5 с). Ожидающие
   записи к ответу не прибавляются: ленте пришлось бы читать Redis для каждой карточки, а точность до секунд счётчику
   просмотров не нужна.
7. **Реакции остаются в базе.** Счётчик лайков и рейтинг (ADR-0081) пересчитываются в транзакции лайка под
   блокировкой цели, и ответ лайка отдаёт точный `{count, liked}`, а событие ADR-0072 — точные счётчики. Перенос в
   Redis сломал бы эту согласованность (ответ и событие расходились бы с базой до сброса, рейтинг — со счётчиком), а
   выигрыш мал: лайк ставят на порядки реже, чем открывают пост, и строка лайка всё равно пишется в базу. Если лайки
   станут горячими, на тот же `IWriteBuffer` переносится только запись событий, а не их подсчёт.

## Последствия

- Нужен Redis с сохранением на диск (AOF или RDB): после перезапуска самого Redis без сохранения теряются
  несброшенные секунды просмотров. Это настройка стенда (E01-06), код её не требует.
- Сырые события для аналитики (E16-18, #217) удобно снимать с того же буфера или декоратором `IViewCounter`.
- Строки `post_views` прошлых суток по-прежнему не удаляются (см. ADR-0071).
- Проверяется автотестами: `backend/tests/Platform.Messaging.IntegrationTests/WriteBufferTests.cs` (пакеты, аренда,
  записи переживают новое подключение; Redis и фейк) и
  `backend/tests/Platform.Modules.Posts.IntegrationTests/ViewFlushTests.cs` (счёт ждёт сброса, переживает перезапуск
  экземпляра, повтор пакета не считает дважды).
