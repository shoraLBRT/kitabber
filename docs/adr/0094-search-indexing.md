# ADR-0094. Индексация постов, блогов и тем в OpenSearch

Статус: предложено (задача E14-01, #84).

## Контекст

FR-SEARCH: поиск по блогам, темам и постам с русской морфологией. Движок выбран в ADR-0001 — OpenSearch; локально он
уже поднимается из `compose.yaml` (`opensearchproject/opensearch:2.19.3`, без security-плагина). Критерии E14-01:
опубликованный пост находится в пределах минуты, снятый и удалённый исчезают, полная переиндексация запускается
командой. Модуль Posts до сих пор не публикует доменных событий (публикация, правка и удаление только сбрасывают кэш
ленты, ADR-0080); Blogs публикует только `BlogSubscribed` (ADR-0092).

## Решение

1. **Новый модуль Search** (хост воркеров, своя схема `search` только для inbox, ADR-0005). Он владеет индексами и
   больше ничем; другие модули о нём не знают.
2. **Движок за интерфейсом.** `ISearchIndex` (upsert документа, удаление, массовая запись, пересоздание индекса).
   Реализации: `OpenSearchIndex` поверх `HttpClient` (REST API, без клиентской библиотеки) и `InMemorySearchIndex` —
   фейк для тестов. Выбор — настройка `Search:Provider` (`OpenSearch` | `InMemory`), адрес — `Search:OpenSearch:Url`
   (по умолчанию `http://localhost:9200`, как в `compose.yaml`; на стенде задаётся явно). Реализация OpenSearch
   проверяется интеграционным тестом на контейнере того же образа, что в `compose.yaml`.
3. **Индексы.** `posts` (заголовок, текст блоков без разметки, блог, автор, дата публикации) и `blogs` (личные блоги и
   темы, поле `kind`: название, никнейм, описание). Текстовые поля — встроенный анализатор `russian` (стемминг
   Snowball и русские стоп-слова), плюс подполе `exact` со `standard`-анализатором для «точного совпадения» E14-03.
   Индекс создаётся с версией в имени (`posts_v1`) за алиасом `posts`: переиндексация пишет в новый индекс и
   переключает алиас, поиск не видит пустоты.
4. **Тонкие события «перечитай меня».** `PostChanged(PostId, OccurredAt)` в Posts.Contracts — при публикации, правке
   опубликованного и удалении (позже — при снятии модерацией). `BlogChanged(BlogId, OccurredAt)` в Blogs.Contracts —
   при правке профиля, смене никнейма и создании темы. Публикуются через `IModuleOutbox<TContext>` своего модуля в
   той же транзакции. Событие не несёт содержимого: потребитель перечитывает текущее состояние через контракт
   владельца и либо записывает документ, либо удаляет его. Так порядок и повторы событий не важны — побеждает
   состояние базы.
5. **Контракты чтения.** `IPostSearchSource` (Posts.Contracts) и `IBlogSearchSource` (Blogs.Contracts): документ
   по id (или `null`, если пост не опубликован или удалён) и постраничный обход всех видимых документов для
   переиндексации. Реализуют их владельцы над своими таблицами; в хосте воркеров регистрируются их контексты.
6. **Полная переиндексация** — команда хоста воркеров:
   `dotnet run --project backend/src/Workers -- search-reindex` (на стенде —
   `docker compose run --rm workers search-reindex`). Обходит источники пачками, пишет в новый индекс, переключает
   алиас, удаляет старый. Ею же заполняется индекс после первого развёртывания и после сида демо-данных.
7. **«В пределах минуты».** Задержка — outbox (`QueryDelay` 1 с) + доставка + refresh интервала OpenSearch (1 с по
   умолчанию); тест проверяет поиск после события с ожиданием не дольше минуты.

## Последствия

- Posts и Blogs получают outbox в своих схемах (миграции `AddPostsOutbox`, у Blogs outbox уже есть).
- Воркерам нужен OpenSearch на стенде: сервис в `deploy/compose.stage.yaml` (образ по тегу и digest, как остальные).
- Поисковое API (E14-02, E14-03) читает те же индексы через расширение `ISearchIndex` запросами.
