# ADR-0079. Обложка блога: целая картинка и положение в процентах

- Статус: предложено 26 ноября 2026, задача E04-04 (#94)
- Требования: [spec.md](../spec.md) (FR-PROFILE: «обложка с выбором положения перетаскиванием»),
  [docs/ui/blog.md](../ui/blog.md) (шапка блога)
- Связанные решения: [ADR-0034](0034-profile-editing-and-avatar.md) (правка профиля, файл через `IMediaLibrary`),
  [ADR-0037](0037-image-delivery-imgproxy.md) (раздача через imgproxy), [ADR-0040](0040-image-component.md)
  (`srcset`), [ADR-0067](0067-image-preview-and-dominant-color.md) (превью и доминирующий цвет)

## Контекст

Владелец блога ставит обложку и перетаскиванием выбирает, какая её часть видна в шапке. Положение должно быть одним
и тем же на десктопе (колонка ленты, 640 px) и на телефоне (390 px), а перетаскивание — работать мышью и пальцем.
Вырезать полосу на клиенте, как аватар, нельзя: тогда положение не поменять без новой загрузки, а для разных
экранов нужна была бы разная полоса.

## Решение

1. **Картинка хранится целой, положение — отдельно.** В `Subsite` — `cover_media_id` и `cover_position` (целое
   0…100, по умолчанию 50, миграция `AddSubsiteCover`). Положение — вертикальное смещение в процентах в смысле CSS
   `object-position: 50% <position>%`: 0 — видна верхняя кромка картинки, 100 — нижняя. Сменить положение — значит
   переписать одно число, файл не меняется.
2. **Одна пропорция шапки на всех экранах.** Обложка — коробка `aspect-ratio: 10 / 3` (640 × 192 на десктопе,
   390 × 117 на телефоне) с `object-fit: cover`. При одной пропорции одинаковое положение показывает одну и ту же
   полосу картинки на любой ширине. Это и есть «одинаково на десктопе и телефоне»; высота шапки на телефоне
   становится меньше прежних 192 px — предложение, требует подтверждения (docs/ui/blog.md).
3. **API.** `PUT /api/v1/profiles/me/cover` (`CoverInput`: `mediaId`, `position`) ставит или двигает обложку,
   `DELETE /api/v1/profiles/me/cover` убирает её; оба только вошедшему и оба отвечают полным `Profile`. Файл
   проверяется как аватар (ADR-0034): изображение этого же аккаунта, чужой и несуществующий файл отвечают
   одинаково; положение вне 0…100 — 400 `validation_failed` с полем `position`. Отдельный адрес, а не поле
   `ProfileInput`: тот заменяет все поля сразу, и форма настроек иначе стирала бы обложку.
4. **Показ.** `Profile.cover` — `ProfileCover`: `id`, `position`, `sources` (вся картинка по ширинам 400, 640, 800,
   1280, 1920 WebP, без обрезки, ADR-0040) и `preview` (доминирующий цвет, ADR-0067); `null` без обложки или когда
   файл больше не изображение.
5. **Клиент.** Обложку меняют прямо в шапке своего блога (`BlogCover.vue`): «Загрузить обложку», затем
   «Изменить положение», «Заменить», «Удалить обложку». В режиме правки поверх картинки — ползунок
   (`role="slider"`, 0…100): pointer events с `touch-action: none` (мышь и палец одним кодом) и стрелки
   (шаг 1, с Shift — 10, Home и End — края). Смещение на `d` пикселей меняет положение на `d / скрытая высота ×
   100` (`utils/cover-position.ts`). Новая картинка уходит в `/bff/media` только по «Сохранить», как аватар.

## Последствия

- Старые файлы обложек не убираются (как и аватаров, ADR-0034) — отдельная уборка медиа.
- Горизонтальное положение не выбирается: картинка шире шапки по пропорции показывается по центру. Если понадобится,
  добавится второе число, а нынешнее значение останется вертикальным.
- Обложка есть только у личного блога; обложку темы зададут инструменты администрации (E11-01).
