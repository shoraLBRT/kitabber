# ADR-0050. Шапка поста с автором и плавающая панель действий

- Статус: предложено (22 ноября 2026), задача E07-04 (#52); действует, пока владелец не решит иначе
- Требования: [spec.md](../spec.md#fr-post-пост) (FR-POST: страница поста, плавающая панель действий),
  [ui/post.md](../ui/post.md) (раскладка на 1440 и 390 px, доступность)
- Связанные решения: [ADR-0025](0025-blogs-subsite-and-profile.md) (блог и профиль, личный блог аккаунта),
  [ADR-0029](0029-posting-rights.md) (в личный блог пишет только владелец), [ADR-0041](0041-post-address-and-slug.md)
  (адрес поста), [ADR-0045](0045-post-block-rendering.md) (отрисовка блоков)

## Контекст

В шапке поста нужен автор — аватар и имя со ссылкой на его блог. Пост знает только `authorAccountId` (модули
общаются через `account_id`), а профиль — это блог. Для поста в личном блоге автор и есть владелец блога (ADR-0029),
для поста в теме блог — тема, и автора нужно найти отдельно. Панель действий по ТЗ включает реакции, комментарии,
закладку, «Поделиться» и репост, но лайк (E10-01, #63), дерево комментариев (E09-02, #58) и полное «Поделиться»
(E07-07, #97) — отдельные задачи.

## Решение

1. **Автор по аккаунту.** Модуль Blogs отдаёт `GET /api/v1/profiles/by-account/{accountId}` — профиль личного блога
   аккаунта (тот же `Profile`, что по id и никнейму), `404 profile_not_found`, если блога нет. Запрос только ищет и
   никогда не создаёт блог чужому аккаунту (в отличие от `/me`). Модуль Posts не меняется и в чужие таблицы не ходит.
2. **Поиск поста** (`frontend/api/posts.ts`, `lookUpPost`) кладёт в найденное `author: Profile | null`: для личного
   блога это сам блог (лишнего запроса нет), для темы — ответ `by-account`. Если блог автора прочитать не удалось,
   `author` — `null`: шапка обходится без автора, страница не падает.
3. **Шапка** (`components/post/PostView.vue`): аватар (`UiAvatar`, декоративный рядом с именем) и имя — ссылка на
   блог автора; тема — отдельной ссылкой, только когда блог не авторский; затем `time` с датой публикации или
   «черновик». Дата — в UTC, как в ленте, чтобы разметка сервера и браузера совпадала.
4. **Панель действий** (`components/post/PostActions.vue`) — `role="toolbar"` «Действия с постом» с подписанными
   кнопками «Нравится», «Комментарии», «Поделиться»; стрелки переводят фокус между ними. Панель — последний элемент
   `article` с `position: sticky; bottom`: она прилипает к низу окна в пределах колонки поста, пока его читают, и
   встаёт на место в конце поста. Ниже 925 px (там есть нижняя панель) отступ снизу — высота нижней панели и
   безопасная зона, ниже 640 px панель во всю ширину колонки.
5. **Что делают кнопки сейчас.** «Нравится» показана и выключена до E10-01. «Комментарии» ведёт к якорю `#comments`
   в конце поста — туда встанет дерево E09-02. «Поделиться» копирует ссылку на канонический адрес и показывает тост;
   системное меню телефона и соцсети — E07-07. Счётчиков пока нет — как в состоянии «Пусто» ui/post.md.
6. **Плавающая «Написать» скрыта на странице поста** (предложение ui/post.md): страница задаёт
   `definePageMeta({ writeButton: false })`, раскладка передаёт это в `ShellLayout`. Иначе кнопка перекрыла бы
   панель над нижней панелью.

## Последствия

- Плюс: шапка и панель приходят с сервера; новый запрос профиля — один и только для поста в теме.
- Плюс: карточка ленты (E08-02, #55) может взять автора тем же запросом.
- Минус: для ленты из многих постов в темах это по запросу на автора; если станет узким местом, нужен пакетный
  запрос профилей по аккаунтам — отдельной задачей.
- Меню «…» (E07-05, #53), закладка, репост и реакции (E10) добавят кнопки в ту же панель.
