# ADR-0056. Форма комментария и ответа: оптимистичная отправка, откат, локальный черновик

- Статус: предложено (23 ноября 2026), задача E09-03 (#59); действует, пока владелец не решит иначе
- Требования: [spec.md](../spec.md#fr-comment-комментарии) (FR-COMMENT: свёрнутое поле «Комментарий…», форма
  ответа), [docs/ui/comments.md](../ui/comments.md)
- Связанные решения: [ADR-0048](0048-comment-tree-and-api.md) (API `POST /posts/{postId}/comments`),
  [ADR-0054](0054-comment-tree-levels.md) (дерево одним упорядоченным списком), [ADR-0018](0018-openid-connect-provider.md)
  (токен только на сервере сайта), [ADR-0032](0032-auth-window-and-guest-actions.md) (окно входа и повтор действия)

## Контекст

API для записи комментария есть с E09-01. Клиенту нужны: поле под постом и форма ответа под комментарием; комментарий
в дереве сразу после нажатия «Отправить», а не после ответа сервера; откат при ошибке без потери текста; черновик,
который переживает перезагрузку; окно входа для гостя. Браузер не держит токен доступа и не знает своего `account_id`
(FR-ID).

## Решение

1. **Отправка через сервер сайта.** Браузер шлёт `{ postId, text, parentId }` в `POST /bff/comments`
   (`server/routes/bff/comments.post.ts`), сервер — в API с токеном сессии и отвечает исходом формы: `sent` с
   комментарием, `refused` с первой причиной из ошибки проверки (пустой текст, слишком глубоко, гостевой родитель),
   `unauthorized` (сессии нет), `error` (всё прочее). Код ответа — всегда 200, поэтому ожидаемый отказ не пишет ошибку в
   консоль браузера.
2. **Оптимистично в дереве.** `useComments.send` сразу ставит в упорядоченный список локальный комментарий
   (`local-N`, глубина родителя + 1): ответ — после прочитанных ответов родителя, комментарий под постом — в конец, как
   его поставит сервер; у всех комментариев выше счётчик `replies` растёт на один, поэтому «Показать ещё N» не
   меняется (`withComment`). Пока сервер не ответил, комментарий приглушён (`aria-busy`, «Отправляется…», автор «Вы»).
   Ответ сервера встаёт на его место (`replaceComment`) и подгружает профиль автора.
3. **Откат.** При любом исходе, кроме `sent`, комментарий убирается и счётчики возвращаются (`withoutComment`), а его
   форма получает текст обратно с причиной под полем (`failures` по цели формы: `post` или id комментария). Закрытая
   форма ответа открывается снова; поле под постом раскрывается. Если человек уже пишет новый текст, он не
   затирается.
4. **Черновик в localStorage.** Ключ `comments.draft.<postId>.<parentId|post>`: текст сохраняется на каждый ввод и
   удаляется пустым вводом. При отправке поле очищается, а черновик остаётся до ответа сервера: после `sent` он
   удаляется, только если в нём всё ещё отправленный текст. Форма с черновиком открывается сразу. Без хранилища форма
   работает, черновик просто не хранится.
5. **Гость.** Свёрнутое поле и «Ответить» гостя открывают окно входа с действием `comment:<postId>:<цель>`; вернувшись
   вошедшим, человек видит открытой ту же форму (`pendingActionWith` находит действие по префиксу,
   `takePendingAction` снимает его).
6. **Кому отвечать нельзя.** «Ответить» нет у гостевого комментария (FR-TG-6), на последнем уровне (`maxDepth` из
   ответа дерева) и у комментария, который ещё отправляется.
7. **Только текст.** Форма — `textarea` до 5000 символов (CommentRules.MaxTextLength), «Отправить» и Ctrl+Enter;
   «Отмена» и Escape закрывают форму ответа, черновик остаётся.

## Последствия

- Отправленный комментарий виден сразу; после перезагрузки он на том же месте, пока нет сортировки (E09-04).
- Под длинным деревом новый комментарий под постом встаёт в конец списка; прокрутка к нему — с E09-07 (ссылка на
  комментарий).
- Черновики не истекают: по одному ключу на форму, удаляются при отправке или очистке поля.
- Не сделано здесь: форматирование и вставка картинки, упоминания (E09-11), вложения (E09-10), права комментирования
  (E09-14), сообщения о карме и лимитах (их ещё нет в API), форма, прижатая к клавиатуре на телефоне (#369).
