# ADR-0045. Отрисовка блоков поста для чтения

- Статус: предложено (22 ноября 2026), задача E07-03 (#51); действует, пока владелец не решит иначе
- Требования: [spec.md](../spec.md#fr-post-пост) (FR-POST), [ui/post.md](../ui/post.md) (типографика лонгрида,
  доступность)
- Связанные решения: [ADR-0023](0023-block-schemas-and-html-cleaning.md) (формат документа, белый список встроенного
  HTML), [ADR-0031](0031-heading-blocks-and-anchors.md) (якорь заголовка `h-<id>`), [ADR-0033](0033-list-block-nesting.md)
  (вложенность списка полем `levels`)

## Контекст

Документ поста хранится как массив блоков (ADR-0023). Странице поста, карточке ленты и предпросмотру нужен один
отрисовщик, который работает при серверном рендеринге, даёт семантическую разметку и не ломается на документе, в
котором есть блок новее клиента (схема версии 1 растёт: медиа и другие блоки добавляют свои задачи).

## Решение

1. **Один компонент.** `frontend/components/post/PostBlocks.vue` принимает документ как есть (`document: unknown`) и
   рисует его; списки — `PostList.vue`. Чтение документа в модель отрисовки — `frontend/utils/post-blocks.ts`
   (`viewBlocks`), без DOM, поэтому одинаково на сервере и в браузере.
2. **Разметка.** `paragraph` — `p`; `header` — `h2` или `h3` с `id="h-<id блока>"` (заголовок поста — `h1`
   страницы); `list` — `ul` или `ol`, вложенный пункт — список внутри `li` родителя (дерево строится из `items` и
   `levels`); `quote` — `figure` с `blockquote` и `figcaption` (подпись только непустая); `delimiter` — `hr`.
3. **Неизвестный блок.** Блок неизвестного типа или с данными, которые не читаются по схеме, рисуется заглушкой
   `p role="note"` «Этот блок пока не умеем показывать.» с `data-block-type`. Документ без блоков — строка «В посте
   пока ничего нет.».
4. **Встроенный HTML** выводится через `v-html` только после `cleanInlineHtml` (`frontend/utils/inline-html.ts`):
   повторная проверка белого списка ADR-0023 без DOM — теги `b strong i em mark br`, ссылка `a` только с `href` по
   схеме `http`, `https`, `mailto` и с `rel="nofollow ugc noopener noreferrer"`; прочие теги отбрасываются с
   сохранением текста, одиночные `<` и `>` экранируются, незакрытые теги закрываются, ссылка в ссылке не допускается.
   Сохранённый сервером документ эта проверка не меняет; она защищает от документа из другого источника и делает
   разметку сервера и браузера одинаковой (нет расхождений при гидратации).

## Последствия

- Плюс: новый тип блока не роняет страницу; добавить его — ветка в `viewBlocks` и в шаблоне.
- Плюс: снимок серверной разметки каждого типа (`tests/post/PostBlocks.spec.ts`) ловит случайные изменения разметки.
- Минус: белый список описан дважды — на сервере (HtmlSanitizer) и на клиенте; меняются вместе.
- Карточка ленты (E08-02, #55) пока показывает простой текст и перейдёт на этот компонент в своей задаче.
