# ADR-0053. Меню «…» поста: автор и читатель, флаги пунктов

- Статус: предложено (23 ноября 2026), задача E07-05 (#53); действует, пока владелец не решит иначе
- Требования: [spec.md](../spec.md#fr-post-пост) (FR-POST: действия автора, меню «…» чужого поста, действия читателя),
  [ui/post.md](../ui/post.md) (меню «…» на 1440 и 390 px)
- Связанные решения: [ADR-0013](0013-ui-components.md) (UiMenu, UiModal, UiSheet), [ADR-0018](0018-openid-connect-provider.md)
  (токен остаётся на сервере сайта), [ADR-0029](0029-post-model-and-api.md) (меняет и удаляет пост только автор),
  [ADR-0050](0050-post-header-and-action-panel.md) (шапка поста и панель действий)

## Контекст

В шапке поста нужно меню «…». Автору — «Редактировать» и «Удалить», читателю — «Пожаловаться», «Скрыть» и
«Скопировать ссылку»; продвижения, донатов и подарков нет (монетизации нет). Готовы из этого только удаление
(`DELETE /api/v1/posts/{id}`, мягкое, только автору — E07-01) и копия ссылки. Редактирование опубликованного поста
в редакторе, жалобы (E15-02, #159) и скрытие из лент (E11-07, #112) — отдельные задачи, а общих фича-флагов
(E01-14, #118) ещё нет. Странице нужно знать, автор ли читатель, но `account_id` вошедшего на страницу не попадает
(FR-ID, ADR-0018).

## Решение

1. **Чей пост — решает сервер сайта.** `lookUpPost` (`frontend/api/posts.ts`) получает `account_id` сессии
   (`event.context.auth.accountId` при первой отрисовке и в `server/routes/bff/post.get.ts`) и кладёт в найденное
   `own: boolean` — совпадает ли он с `authorAccountId` поста. Сам id вошедшего на страницу не уходит. `own` — только
   выбор пунктов меню; права проверяет API (`posts.not_author`).
2. **Состав меню** — чистая функция `postMenuItems(own, features)` (`frontend/utils/post-menu.ts`): автору
   «Редактировать» и «Удалить», остальным (и гостю) «Пожаловаться», «Скрыть», «Скопировать ссылку».
3. **Флаги пунктов без готового функционала.** «Редактировать», «Пожаловаться» и «Скрыть» показываются, только если
   включён их флаг: `runtimeConfig.public.features` — `postEdit`, `postReport`, `postHide`, по умолчанию `false`.
   Nuxt берёт их из окружения при старте (`NUXT_PUBLIC_FEATURES_POST_EDIT=true` и так далее), новая сборка не нужна.
   Задача, которая делает пункт, включает его флаг по умолчанию и подключает событие `action` компонента `PostMenu`.
   Когда появятся общие флаги E01-14 (#118), эти три переезжают туда.
4. **Удаление с подтверждением.** «Удалить» открывает окно «Удалить пост?» с «Отмена» и «Удалить». Подтверждение
   идёт через сервер сайта: `DELETE /bff/post?id=…` (`server/routes/bff/post.delete.ts`) вызывает API с токеном
   сессии и передаёт его статус. Удалённый пост уводит в его блог (или тему) с тостом «Пост удалён»; сбой оставляет
   окно открытым с тостом «Не удалось удалить пост».
5. **Раскладка.** Кнопка «Меню поста» (значок «…») стоит в конце шапки. На широком экране — выпадающее меню UiMenu,
   на телефоне (уже 640 px) — нижняя шторка UiSheet с теми же пунктами, как в ui/post.md.

## Последствия

- Пока флаги выключены, автор видит только «Удалить», читатель — только «Скопировать ссылку».
- Остальные действия автора и читателя из FR-POST (снять с публикации — E07-08, закрепить, право комментирования,
  статистика, заблокировать автора, скрыть тему, пост-ответ) добавляют свои задачи — в тот же список
  `postMenuItems`, со своим флагом, если пункт появляется раньше функционала.
- Флаги в `runtimeConfig` переключаются перезапуском сайта, а не на лету и не для части людей; этого достаточно до
  E01-14.
