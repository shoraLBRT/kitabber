# ADR-0093. Лента уведомлений и счётчик непрочитанных

Статус: предложено (задача E12-02, #83).

## Контекст

FR-NOTIFY: лента уведомлений со счётчиком непрочитанных; макет — [docs/ui/notifications.md](../ui/notifications.md)
(панель «колокольчика» на десктопе, страница `/notifications` и вкладка нижней панели на телефоне). Критерии задачи:
счётчик в шапке, открытие панели помечает показанные прочитанными, лента подгружается по курсору. Уведомления
пишет модуль Notifications в хосте воркеров (ADR-0092); в API его не было. Группировка однотипных событий,
«Прочитать все» и отписка от треда — E12-03, доставка в реальном времени — E12-04, настройки — E12-05.

## Решение

1. **Модуль Notifications и в хосте API** (`AddNotificationsModule`): та же схема `notifications`, только чтение
   ленты и отметка прочтения; потребители событий остаются в воркерах. Миграция не нужна: индекс ленты
   `ix_notifications_feed (recipient, created_at desc, id desc)` заложен в E12-01.
2. **API** (только вошедшему, чужие уведомления не видны и не меняются):
   - `GET /api/v1/notifications/me?cursor=&limit=` — уведомления по убыванию `(created_at, id)`, курсор ADR-0006,
     `Cache-Control: private, no-store`. Элемент `NotificationView`: тип строкой (`comment_reply`, `post_comment`,
     `reaction`, `mention`, `new_subscriber`; клиент показывает незнакомый тип простой строкой), действующее лицо
     (`NotificationActorView` — личный блог из одного пакетного `IBlogDirectory.CardsAsync` на страницу), ссылки на
     пост и комментарий, вид реакции, время, `read`.
   - `GET /api/v1/notifications/me/unread` — `{ unread }`, число непрочитанных.
   - `POST /api/v1/notifications/me/read` с `{ ids }` (от 1 до 100, иначе `validation_failed`) — ставит `read_at`
     своим непрочитанным из списка (чужие и уже прочитанные не меняются, повтор безопасен) и отвечает новым
     `{ unread }`, чтобы клиент обновил счётчик без второго запроса.
3. **Отметка «по показу»**: клиент после каждой загруженной страницы (панель или страница, первая или следующая)
   отправляет id показанных непрочитанных. Точки непрочитанного на этих строках остаются до следующего открытия,
   чтобы человек видел, что нового. Отдельного «Прочитать все» нет до E12-03.
4. **Клиент**: счётчик читает браузер после показа страницы (`useUnreadNotifications`, `/bff/notifications/unread`),
   заново при входе и выходе; гостю и при сбое счётчика нет. Колокольчик — кнопка с числом в подписи
   («Уведомления, 3 непрочитанных», больше 99 — «99+»), открывает панель (`--size-aside`, до 70 % высоты, закрытие по
   `Esc`, клику вне и открытию строки) со ссылкой «Все уведомления →». На телефоне счётчик на вкладке
   «Уведомления», вкладка ведёт на `/notifications`. Строка ведёт на пост (`/u/-/<id поста>#comment-<id>`: пост
   находится по id и уводит на канонический адрес, ADR-0041) или, для подписчика, в его блог.
5. **Без реального времени**: счётчик обновляется при загрузке страницы, входе и отметке прочтения. Живое обновление
   через SignalR (ADR-0064) — E12-04.

## Последствия

- Заголовка поста и текста комментария в строке нет: у `IPostDirectory` и `ICommentDirectory` нет пакетного чтения
  заголовков и отрывков; строка говорит «ответил на ваш комментарий» без цитаты. Добавить вместе с группировкой
  (E12-03) или отдельной задачей.
- Уведомление от человека, заблокированного после того, как оно пришло, остаётся в ленте: подавление — только при
  записи (ADR-0092).
- Счётчик — `COUNT` по индексу ленты получателя; при больших объёмах — кэш числа, когда появится E12-04.
