# ADR-0002. Аккаунты: отдельный модуль Identity и вход по OpenID Connect

- Статус: предложено (19 ноября 2026); действует, пока владелец не решит иначе
- Требования: [unified-accounts.md](../unified-accounts.md)
- Задачи: эпик E18, затем E03

## Контекст

В будущем аккаунты нескольких проектов владельца будут объединены. Сейчас объединение не делаем, но не хотим
потом переписывать вход, сессии и все ссылки на пользователя.

## Решение

1. Учётные данные живут в модуле `Identity` со своей схемой `identity`. Остальные модули хранят только
   `account_id` (UUID v7) без внешних ключей на эту схему.
2. `Identity` — провайдер OpenID Connect (библиотека OpenIddict) внутри монолита. Веб-клиент и админ-панель
   входят по коду авторизации с PKCE; токены хранит серверная часть Nuxt (BFF), браузер получает только
   защищённую cookie.
3. API проверяет токены по адресу провайдера из настроек (`Auth:Authority`). Смена провайдера — смена
   настройки.
4. Почта нормализуется и подтверждается; внешние входы хранятся парами «провайдер, субъект».
5. Изменения аккаунта публикуются событиями `account.*` с версией схемы.
6. Роли и права kitabber хранит модуль `Moderation`, а не `Identity`.

## Последствия

- Плюс: при слиянии `Identity` выносится в сервис или заменяется внешним провайдером без изменения остальных
  модулей.
- Плюс: админ-панель и будущие мобильные приложения получают вход «бесплатно» — как ещё один клиент OIDC.
- Минус: около пяти дней работы сверх простого входа по cookie; протокол сложнее в отладке.
- Минус: вход и API зависят от корректной настройки ключей подписи; ключи — секрет окружения.

## Рассмотренные варианты

- **Простой вход по cookie в монолите.** Быстрее сейчас, но слияние означало бы переписать вход во всех
  проектах сразу.
- **Готовый внешний сервис (Keycloak и подобные) с первого дня.** Ближе к целевой картине, но это отдельная
  система в эксплуатации уже на старте; вернёмся к варианту при слиянии.

## Открытые вопросы для владельца

- Какие проекты будут объединяться и на каком стеке их аккаунты — от этого зависит, станет ли kitabber
  источником аккаунтов или клиентом.
- Нужен ли общий вход (SSO) между проектами или только общая база аккаунтов.
