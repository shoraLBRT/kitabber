# ADR-0054. Дерево комментариев: чтение по уровням, подгрузка глубоких ответов, сворачивание веток

- Статус: предложено (23 ноября 2026), задача E09-02 (#58); действует, пока владелец не решит иначе
- Требования: [spec.md](../spec.md#fr-comment-комментарии) (FR-COMMENT: дерево с линиями веток, сворачивание ветки,
  подгрузка длинных веток), [docs/ui/comments.md](../ui/comments.md)
- Связанные решения: [ADR-0048](0048-comment-tree-and-api.md) (модель, путь, API; оставила подгрузку глубоких веток
  этой задаче), [ADR-0006](0006-rest-api-conventions.md) (REST и ошибки)

## Контекст

API E09-01 отдаёт всё дерево поста. Пост с тысячей комментариев должен открываться без зависаний, а глубокие ответы —
подгружаться по кнопке. Узкий экран телефона вмещает меньше уровней отступа, чем десктоп. Клиенту нужно знать, сколько
ответов он не получил, чтобы подписать кнопку «Показать ещё N ответов» и свёрнутую ветку.

## Решение

1. **Чтение по уровням.** `GET /api/v1/posts/{postId}/comments` и `GET /api/v1/comments/{id}/branch` принимают
   необязательный `levels` (от 1 до 32, иначе 400 `validation_failed` с полем `levels`): дерево отдаёт комментарии
   глубины не больше `levels`, ветка — свой корень и ответы не глубже `levels` уровней под ним. Без `levels` — всё, как
   было.
2. **`replies` у каждого комментария** — число всех ответов под ним на любой глубине, и отданных, и нет. База читает
   ветку тем же одним запросом по пути; счёт и отбор уровней — один проход по списку в порядке пути
   (`CommentTree.Shown`): ответы комментария — идущие за ним более глубокие. Свой запрос с подсчётом в SQL не нужен:
   тысяча строк поста читается за один запрос по индексу, а экономия — в размере ответа и в отрисовке.
3. **Клиент читает 6 уровней на широком экране и 3 на телефоне** (пороги из docs/ui/comments.md, `commentLevels`);
   выбор — по ширине окна в момент чтения. Кнопка «Показать ещё N ответов» стоит там, где дерево остановилось, и читает
   ветку этого комментария на столько же уровней; ветка встаёт на место его части списка (`withBranch`). N — ответы,
   которые не лежат ни под одним показанным ответом (`nestComments`).
4. **Сворачивание** — на клиенте, без запроса: линия ветки слева от ответов — кнопка «Свернуть ветку» с
   `aria-expanded`; свёрнутая ветка оставляет «Развернуть · N ответов». Состояние не сохраняется между визитами.
5. **Комментарии читаются в браузере после показа поста** (`useComments`): серверная отрисовка поста их не ждёт, пост
   остаётся при сбое комментариев. Черновику комментарии не показываются (API для него отвечает 404).
6. **Авторы** — `GET /api/v1/profiles/by-account/{accountId}` на каждого ещё не известного автора, не больше 6
   одновременно; не прочитанный профиль оставляет подпись «Автор». Гостевой комментарий подписан именем гостя со
   ссылкой на источник. Один запрос на всех авторов — задача #367.

## Последствия

- Тысяча комментариев проверена в браузере: дерево рисуется без длинных задач главного потока, ветка сворачивается
  сразу. Пагинации корневых комментариев нет; если посты с десятками тысяч комментариев станут реальностью, нужен
  курсор по пути (ADR-0048) поверх `levels`.
- Страница треда (E09-06) заменит «Показать ещё» на «Продолжить ветку» для самых глубоких уровней, если владелец так
  решит; API для неё уже есть (`branch?levels=`).
- Свёрнутые ветки, сортировка (E09-04), подсветка новых и ссылка на комментарий — своими задачами.
