# ADR-0089. «Моя лента»: посты подписок по дате, исключения читателя через контракт, без общего кэша

- Статус: предложено 26 ноября 2026, задача E08-04 (#80).
- Требования: [spec.md](../spec.md) (FR-FEED: «Моя лента» — подписки; FR-SUB: чёрный список, скрытие поста и темы
  из лент), [docs/ui/feed.md](../ui/feed.md)
- Связанные решения: [ADR-0043](0043-fresh-feed.md) (лента «Свежее» и её курсор), [ADR-0051](0051-feed-infinite-scroll-and-return.md)
  (подгрузка и возврат), [ADR-0080](0080-feed-cache.md) (кэш страниц лент), [ADR-0085](0085-blog-subscriptions.md)
  (подписки и контракт `IBlogSubscriptions`), [ADR-0018](0018-openid-connect-provider.md) (токен остаётся на сервере сайта)

## Контекст

«Моя лента» — посты блогов и тем, на которые подписан читатель. Подписки живут в модуле Blogs (ADR-0085), посты — в
модуле Posts; модули не читают чужие таблицы. Критерии задачи требуют, чтобы скрытое и заблокированное не попадало в
ленту, но сами списки — чёрный список (E11-06, #81) и скрытые посты и темы (E11-07, #112) — ещё не сделаны. Лента
у каждого читателя своя, а кэш страниц лент (ADR-0080) общий для всех и сбрасывается только изменениями постов.

## Решение

1. **Адрес и права.** `GET /api/v1/feeds/my` в модуле Posts, только для вошедшего (`401` гостю), ответ —
   `CursorPage<FeedPostView>`, как у остальных лент.
2. **Что в ленте.** Модуль Posts спрашивает `IBlogSubscriptions.SubscribedBlogsAsync` и берёт опубликованные посты,
   у которых блог — один из блогов подписки **или** автор — владелец личного блога из подписки. Подписка на человека
   приносит все его посты, и в темах тоже (как на DTF); подписка на тему — посты темы. Черновики и удалённые не
   попадают. Без подписок ответ — пустая последняя страница без запроса к постам.
3. **Порядок.** По дате публикации, новые сначала, курсор ленты «Свежее» `(published_at, id)` (ADR-0043). Сортировка
   «по популярности» из FR-FEED — отдельная задача: ей нужен свой курсор `(score, id)` по `posts.post_hotness` (#412).
4. **Исключения читателя.** Контракт `Posts.Contracts.IFeedExclusionSource.ForReaderAsync(accountId)` отдаёт
   `FeedExclusions` — скрытые посты, скрытые блоги и темы, заблокированных авторов. Модуль, который ведёт список,
   реализует источник по своим таблицам и регистрирует его в DI; лента спрашивает все зарегистрированные источники и
   отбрасывает объединение. Пока источников нет, ничего не исключается; задачи #81 и #112 добавляют свои источники и
   не меняют ленту. Правило проверено тестом с фейковым источником.
5. **Без кэша.** Страница «Моей ленты» не кладётся в общий кэш лент (ADR-0080): ключ по аккаунту должен был бы
   сбрасываться ещё и подпиской, отпиской, скрытием и блокировкой из других модулей, а ошибка в ключе показала бы
   одному читателю ленту другого. Запрос строится по индексу ленты «Свежее», а подписок у читателя немного. Ответ
   API и маршрут сайта `/bff/my-feed` помечены `Cache-Control: private, no-store`. К кэшу вернёмся по данным
   нагрузки, с ключом по аккаунту и событиями подписок.
6. **Сайт.** Страница `/my`: первая страница читается на сервере сайта с токеном пользователя, следующие — через
   `/bff/my-feed` (ADR-0018), подгрузка и возврат — `useFeed` (ADR-0051). Гостю — «Войдите…» с кнопкой окна входа.
   Пустая лента предлагает до шести тем (`GET /api/v1/topics`, читаются в браузере, только когда лента пуста) и
   «Найти авторов в «Свежем»»: «Рейтинга», куда вела кнопка в макете, ещё нет. Текст один для «нет подписок» и «у
   подписок нет постов»: API их не различает.

## Последствия

- Скрытое и заблокированное исключается из «Моей ленты», как только #81 и #112 зарегистрируют источники; в общих
  лентах («Свежее», «Популярное», лента блога) исключения читателя пока не применяются — они кэшируются для всех, и
  это решают те задачи.
- Каждый запрос «Моей ленты» идёт в базу; список блогов подписки передаётся в запрос массивом.
- На телефоне до `/my` пока нельзя дойти из интерфейса: вкладок лент под шапкой (docs/ui/feed.md) ещё нет —
  отдельная задача #413.
