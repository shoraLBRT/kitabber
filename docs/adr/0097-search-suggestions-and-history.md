# ADR-0097. Подсказки поиска в шапке и история запросов

Статус: предложено (задача E14-02, #85).

## Контекст

FR-SEARCH: быстрый поиск в шапке с подсказками и историей запросов. Критерии E14-02: подсказки появляются с задержкой
ввода, история хранится локально и очищается, на телефоне поиск открывается отдельным экраном. Индексы постов, блогов
и тем уже ведёт модуль Search в хосте воркеров (ADR-0094); в API модуля поиска не было. Страница результатов с блоками
«Блоги», «Темы», «Посты» и фильтрами — следующая задача E14-03.

## Решение

1. **Модуль Search в API — только чтение.** `AddSearchModule()` регистрирует тот же `ISearchIndex` по
   `Search:Provider` и `Search:OpenSearch:Url` (своей схемы и базы в API у модуля нет) и эндпоинт
   `GET /api/v1/search/suggestions?q=`. На стенде API получает тот же адрес OpenSearch, что воркеры, но не ждёт его
   при старте: без OpenSearch подсказки отвечают `503 search_unavailable`, остальное API работает.
2. **Подсказки — префикс последнего слова.** `ISearchIndex.SuggestAsync` — `multi_match` типа `bool_prefix` с
   `operator: and` по тем же полям, что `SearchAsync`: слова до последнего — с морфологией, последнее — как начало
   слова («кош» находит «кошка»). Возвращаются документы целиком (`_source`), а не только id: пост показывается по
   заголовку или началу текста из индекса, без похода в модуль Posts. Блоги и темы — карточками `IBlogDirectory` с
   текущими названием, никнеймом и аватаром; блог, пропавший из Blogs, не показывается.
3. **Ответ.** `{ query, blogs: [до 4: id, kind (personal|topic), name, nickname, avatarSources], posts: [до 5: id,
   blogId, title, excerpt (до 140 знаков), publishedAt] }`. Запрос обрезается и схлопывает пробелы; пустой и длиннее
   100 знаков — `400 validation_failed` по полю `q`. Ответ `Cache-Control: private, no-store`. Пост открывается по
   `/u/<blogId>/<id>`, страница поста ведёт на канонический адрес (ADR-0041).
4. **Чёрный список.** Подсказки открыты гостю; вошедшему не показываются посты и личный блог аккаунтов из его
   чёрного списка (`IBlockList`, ADR-0091). Темы не скрываются, даже если владелец темы заблокирован: тема общая.
   Скрытые из лент посты и темы (E11-07, `IFeedExclusionSource`) в поиске видны: поиск — не лента, человек ищет
   нужное сам.
5. **Лимит частоты.** Своя политика `search.suggestions` — 120 запросов в минуту на аккаунт (гостя — на адрес) сверх
   `Default` (ADR-0016). Клиент шлёт запрос после паузы ввода 300 мс и отменяет устаревшие.
6. **История запросов — в браузере, отдельно для каждого аккаунта.** Сервер историю не хранит. `localStorage`,
   до 10 последних запросов без повторов, новые сверху; очищается кнопкой «Очистить» (и по одному запросу). Ключ —
   `search.history.guest` для гостя и `search.history.<ключ>` для вошедшего, где ключ — HMAC-SHA-256 от `account_id`
   на `sessionPassword` сайта, первые 16 байт в base64url: сервер сайта кладёт его в состояние страницы вместе с
   «вошёл/не вошёл». Так история одного аккаунта не показывается другому аккаунту в том же браузере, а сам
   `account_id` странице не виден (FR-ID). Запрос попадает в историю, когда человек нажал Enter или открыл
   подсказку.
7. **Интерфейс.** На десктопе кнопка поиска в шапке раскрывает поле на ширину ленты и затемняет страницу (Esc,
   клик по затемнению — закрыть); на телефоне (уже `breakpoint.sm`) поиск открывается отдельным экраном поверх
   страницы с кнопкой «Отмена». Пустое поле показывает историю, ввод — подсказки; стрелки вверх и вниз выбирают
   строку, Enter открывает её. Состояния: загрузка (скелетон строк), «Ничего не нашлось», ошибка с «Повторить».
   Enter без выбранной строки пока только записывает запрос в историю — страница результатов появится в E14-03.

## Последствия

- Индекс OpenSearch теперь читают два хоста; изменения схемы индекса (ADR-0094) учитывают и подсказки.
- Браузер ходит за подсказками через BFF сайта `/bff/search-suggestions` (ADR-0018): токен вошедшего остаётся на
  сервере, а API знает читателя и применяет его чёрный список.
- Предложения, ждут подтверждения владельца: размеры списков (4 блога, 5 постов, 10 запросов истории), пауза 300 мс,
  лимит 120 в минуту, видимость скрытых из лент постов в поиске, Enter без страницы результатов.
