# ADR-0120. Хэштеги: разбор при публикации и лента тега

Статус: предложено (E11-08, #113). Требования: FR-TOPIC («хэштеги в тексте поста ведут на ленту тега»),
[ADR-0043](0043-fresh-feed.md) (курсор свежей ленты), [ADR-0080](0080-feed-cache.md) (кэш страниц лент),
[ADR-0091](0091-black-list.md) (исключения читателя после общего кэша), [ADR-0094](0094-search-indexing.md) (текст поста
без разметки).

## Контекст

Хэштег пишут прямо в тексте поста. Нужно: найти теги поста, отдать ленту тега и превратить тег в тексте в ссылку на
неё. Подсказка тегов и упоминаний при вводе в редакторе — отдельная задача E05-21 (#137), здесь её нет.

## Решение

1. **Что такое тег.** `#` и слово из букв, цифр и `_` (с комбинирующими знаками, то есть любой алфавит), в котором есть
   хотя бы одна буква, длиной до 64 символов. Перед `#` не стоит буква, цифра, `_`, `&` или ещё один `#`: так
   `site.ru/page#part`, `слово#внутри`, сущность `&#39;` и `##тег` — не теги; `#2026` — тоже не тег. Слово длиннее 64
   символов не тег вовсе (не обрезается). Правило одно на сервере (`Hashtags`) и в клиенте (`utils/hashtags.ts`).
2. **Регистр не различается.** Тег хранится строчными (`ToLowerInvariant`); `#Кино`, `#КИНО` и `#кино` — один тег.
3. **Где хранятся.** Столбец `posts.posts.tags text[]` (миграция `AddPostTags`) с GIN-индексом по опубликованным
   неудалённым постам; отдельной таблицы и отдельного модуля нет: теги — часть поста, лента читает свою же таблицу.
   Не больше 20 тегов на пост, первые по тексту, без повторов.
4. **Когда извлекаются.** Сущность `Post` берёт теги из текста блоков без разметки (`PostText`, ADR-0094) при
   публикации и при каждой правке опубликованного поста; у черновика тегов нет. Так их получают и пост автора, и
   импортированный из Telegram, и демо-данные — у всех один путь через `Post.Publish`.
5. **Лента тега** — `GET /api/v1/feeds/tags/{tag}`: опубликованные посты с тегом, новые сверху, курсор свежей ленты
   (ADR-0043). Тег принимается в любом регистре, с `#` или без; слово, которое не тег, — `400 validation_failed`;
   тег без постов — пустая страница, не 404 (ссылка на тег не ломается). Страницы кэшируются как у свежей ленты
   (ключ `tag:<тег>`, ADR-0080), исключения читателя применяются после кэша (ADR-0091). Запрос — пересечение массивов
   (`&&`), которое обслуживает GIN-индекс.
6. **Клиент.** Каждый тег в тексте блоков — ссылка `<a class="hashtag" href="/tags/<тег строчными>">` (её ставит
   `linkHashtags` после чистки разметки, внутри ссылки тег не трогается); обычный щелчок переходит без перезагрузки.
   Страница `/tags/<тег>`: заголовок `#тег`, лента с пустым состоянием и ошибкой; другой регистр — 301 на строчный
   адрес, не тег — 404. Адрес `tags` уже зарезервирован для тем (ADR-0084).

## Последствия

- Посты, опубликованные до миграции, тегов не получают, пока их не отредактируют: перерасчёта нет, данных в
  production ещё нет.
- Теги не отдаются отдельным полем в `PostView` и `FeedPostView`: клиент находит их в тексте сам. Если понадобится
  список тегов поста (например, для подсказки E05-21 или каталога тегов), его можно добавить из того же столбца.
- Тег в подписи к изображению и в цитате тоже тег: разбирается весь текст блоков, как для поиска.
