# ADR-0095. Набор реакций: справочник и графика из открытого набора эмодзи

Статус: предложено (задача E02-12, #86).

## Контекст

FR-REACT и FR-UI: сдержанный набор реакций без насмешек и пошлости, графика — из открытого набора. Критерии задачи:
набор задаётся справочником в админке, лицензия графики записана в docs, реакции выглядят одинаково на всех
платформах. До задачи была только реакция «Нравится» (E10-01, ADR-0061) — `ReactionKind.Like`, сердечко Lucide
в `ReactionRow`; вес реакции в рейтинге задаётся в коде (`ReactionWeights`, ADR-0081). Выбор реакции из набора,
смена и долгое нажатие — E10-02 (#87); редактор справочников в админ-панели — E15-12 (#168), а сама админ-панель
со входом и ролями — E15-10 (#160) и E15-11 (#167), их ещё нет.

## Решение

1. **Графика — Fluent Emoji, вариант Flat** (Microsoft, <https://github.com/microsoft/fluentui-emoji>), лицензия
   **MIT**. Совместима с проектом без условий, кроме сохранения уведомления об авторских правах: текст лицензии лежит
   рядом с картинками в `brand/reactions/LICENSE`, а витрина `/reactions` показывает строку об авторстве.
   Noto Emoji отвергнут: в репозитории сейчас смешаны OFL (шрифты) и Apache-2.0 (картинки) с неясной границей;
   Twemoji (CC BY 4.0) требует указания авторства при каждом показе; OpenMoji (CC BY-SA 4.0) — копилефт на графику.
   Набор и графика DTF не используются.
2. **Одинаково на всех платформах**: реакция рисуется своим SVG (`ReactionIcon`, `<img>` фиксированного размера
   16/24/40 px), а не символом эмодзи системного шрифта. Картинки собираются в бандл сайта
   (`frontend/utils/reaction-graphics.ts`) из `brand/reactions/` — рядом с прочей графикой бренда (ADR-0011),
   потому что приложения не держат файлов картинок (`brand.spec.ts`); источник и лицензия записаны в `brand.json`
   (`reactions`). Внешних запросов нет; тест проверяет, что в SVG нет скриптов и ссылок.
3. **Коды реакций и их картинки — закрытый список в коде** (`ReactionGraphics.Codes` в модуле Reactions и тот же
   список картинок в клиенте; тест клиента сверяет оба): `like`, `heart`, `smile`, `clap`, `idea`, `wow`, `sad`.
   Новая картинка приходит с изменением кода, потому что её надо положить в бандл; админка её не загружает.
4. **Справочник — таблица `reactions.reaction_set`** (`code` — ключ, `title` до 40 символов, `position`, `enabled`).
   Набор по умолчанию — справочные данные миграции `AddReactionSet` (есть в каждом окружении, демо-сидер не нужен):
   «Нравится» (`like`, тот же код, что у существующего лайка), «Тепло», «Улыбка», «Браво», «Полезно», «Удивительно»,
   «Грустно». Справочник решает, какие реакции предлагаются, под каким названием и в каком порядке.
   Тесты интеграции сохраняют таблицу при очистке базы (`KeepTables`).
5. **API**: `GET /api/v1/reactions/set` без входа — включённые записи по `position`, элемент `ReactionSetItem
   { code, title }`. Код без картинки в этой сборке не отдаётся, клиент к тому же пропускает незнакомый код.
6. **Правка справочника** — эндпоинты администратора и экран в админ-панели — делает E15-12 (#168) вместе с прочими
   справочниками, когда появятся вход в админку и роли (E15-10, E15-11). До этого справочник меняется миграцией.
7. **Веса новых реакций не задаются здесь**: `ReactionKind` по-прежнему только `Like`, и ставить можно только его.
   Виды реакций в `Reaction.Kind`, их веса в `ReactionWeights` (неотрицательные, ADR-0081) и перевод ряда реакций
   на картинки набора — E10-02 (#87). Выключенная в справочнике реакция остаётся на том, на что её уже поставили.

## Последствия

- Витрина `/reactions` (страница дизайн-системы, без строк словаря, как `/ui`) показывает набор в обеих темах,
  загрузку, пустой справочник и ошибку; адрес `reactions` зарезервирован для тем.
- Обновление Fluent Emoji не приходит само: картинки скопированы в репозиторий, их меняют изменением кода.
- Если E10-02 или E15-12 захотят добавлять реакции без выкладки, понадобится загрузка картинок через модуль Media
  и решение о проверке их лицензии — это отдельное решение.
