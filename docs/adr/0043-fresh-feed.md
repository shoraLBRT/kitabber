# ADR-0043. Лента «Свежее»: запрос по постам и курсор по времени публикации

- Статус: предложено (22 ноября 2026), задача E08-01 (#54); действует, пока владелец не решит иначе
- Требования: [spec.md](../spec.md#fr-feed-ленты) (FR-FEED: «Свежее» — хронология; курсорная пагинация с бесконечной
  подгрузкой, «Показать новые»), [ui/feed.md](../ui/feed.md) (адрес `/new`)
- Связанные решения: [ADR-0001](0001-stack.md) (модуль `Feeds` в списке модулей),
  [ADR-0006](0006-rest-api-conventions.md) (курсоры, `?cursor=&limit=`, `invalid_cursor`),
  [ADR-0029](0029-post-model-and-api.md) (модель поста, событий у постов пока нет)

## Контекст

«Свежее» — первая лента: все опубликованные посты по времени, страницами по курсору, без пропусков и дублей, когда
сверху появляются новые посты. ADR-0001 называет отдельный модуль `Feeds`, но модуль не читает чужие таблицы, а у
постов пока нет событий (outbox появится с первым потребителем, ADR-0029). Ленте «Свежее» не нужны свои данные: это
запрос к таблице постов. Фильтр по рейтингу придёт с реакциями (E09), «Популярное» и «Моя лента» — со своими данными
(горячесть, подписки).

## Решение

1. **Где живёт.** `GET /api/v1/feeds/fresh` — в модуле `Posts` (`FreshFeedEndpoints`, тег OpenAPI `Feeds`): запрос к
   своей схеме `posts`, без чужих таблиц. Модуль `Feeds` выделяется, когда ленте понадобятся свои данные (горячесть,
   подписки, скрытое) — тогда он строит проекцию по событиям постов, а адрес `/api/v1/feeds/…` не меняется.
2. **Порядок и курсор.** Посты со статусом «опубликован» и без удаления, по убыванию `(published_at, id)`. Курсор —
   `FreshFeedCursor(PublishedAt, Id)` последнего поста страницы в формате ADR-0006 (`CursorCodec`). Следующая страница —
   сравнение строк `(published_at, id) < (@at, @id)` (Npgsql `EF.Functions.LessThan` по кортежам). Новый пост
   публикуется позже всех, поэтому попадает выше курсора: страницы после первой не сдвигаются, пост не повторяется и
   не пропадает. `id` разрешает равенство времени, порядок полный.
3. **Индекс.** Частичный индекс `ix_posts_fresh_feed` по `(published_at DESC, id DESC)` с условием
   `status = 'Published' AND deleted_at IS NULL`: страница на любой глубине — один проход по диапазону индекса.
4. **Ответ.** `CursorPage<PostView>` — `{items, nextCursor}`; элемент — тот же `PostView`, что у `GET /posts/{id}`.
   Автор и блог в элементе — только идентификаторы; карточка с ними — E08-02 (#55).
5. **Клиент.** Страница `/new`: первая страница рендерится на сервере (`useAsyncData`), следующие браузер берёт из
   API напрямую (лента публичная). Ссылка на пост — `/u/<id блога>/<id>-<слаг>`, страница поста ведёт её 301 на
   канонический адрес (ADR-0041). До E08-03 (#56) следующая страница — по кнопке «Показать ещё»; клиент не показывает
   пост дважды, даже если страницы пересеклись.

## Последствия

- Пост, снятый с публикации или опубликованный задним числом, может сдвинуть страницы, уже прочитанные клиентом:
  снятия с публикации пока нет; если появится смена `published_at`, курсор останется верным для новых запросов.
- Фильтр рейтинга (все, от −10, от +5, от +10) требует рейтинга поста; он добавится условием к этому запросу или
  переедет в модуль `Feeds` вместе с проекцией.
- «Показать новые» (E08-03) может спрашивать первую страницу и сравнивать с первым показанным постом — отдельный
  курсор «назад» сейчас не нужен.
