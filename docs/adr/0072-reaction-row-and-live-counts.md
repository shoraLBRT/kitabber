# ADR-0072. Ряд реакций: общий компонент, сортировка по количеству и живые счётчики через тему поста

- Статус: принято
- Дата: 2026-11-26
- Задачи: E10-03 (#72); опирается на [ADR-0061](0061-likes.md) (лайки, модуль Reactions),
  [ADR-0019](0019-realtime-channel.md) (хаб и темы), [ADR-0064](0064-realtime-event-order.md) (порядок событий)

## Контекст

FR-REACT: «Ряд реакций со счётчиками». Задача E10-03 — показать поставленные реакции: отсортировать по количеству,
выделить свою, обновлять счётчики в реальном времени. Сейчас вид реакции один — «Нравится» (E10-01); набор реакций
(E02-12, #86) и выбор и смена реакции долгим нажатием (E10-02, #87) — свои задачи. Канал реального времени есть
(SignalR, темы `account:<id>` и `post:<id>`), но ни один модуль в него ещё не публиковал.

## Решение

1. **Событие `reactions.changed` в теме `post:<id>`.** Модуль Reactions после каждой настоящей перемены (поставлен
   новый лайк, снят существующий) публикует через `IRealtimePublisher` новые счётчики цели:
   `{target: "post" | "comment", targetId, reactions: [{kind: "like", count}]}`; вид, которого никто не поставил, не
   перечисляется. Повтор, отказ и снятие несуществующего лайка ничего не публикуют. Событие никого не называет:
   свою отметку читатель знает из своих чтений и изменений. Комментарии едут в тему своего поста, так что странице
   хватает одной подписки. Сбой канала не отменяет изменение — пишется предупреждение в журнал, читатели увидят
   счётчик при следующем чтении.
2. **Счётчик абсолютный, порядок — внутри темы.** Событие несёт итоговое число, а не «+1», поэтому повтор и
   пропуск события не накапливают ошибку. Порядок событий одной темы сохраняется (ADR-0064); после обрыва
   пропущенные события не воспроизводятся — страница покажет точные числа при следующем чтении.
3. **Клиент.** `useLikes` подписывается на тему открытого поста (только вошедший: у гостя канала нет, ADR-0019) и
   меняет счётчик цели, оставляя свою отметку; пока своё изменение цели не отвечено, событие о ней пропускается —
   ответ сервера принесёт число. Событие чужой темы и неизвестные виды реакций пропускаются.
4. **Общий компонент `ReactionRow`.** Панель действий поста (вариант `panel`) и строка комментария (`compact`)
   рисуют реакции одним компонентом: виды с количеством больше нуля, по убыванию количества, при равенстве — в
   порядке `reactionKinds`; «Нравится» остаётся в ряду и без счётчика, чтобы было что нажать. Своя реакция —
   акцентный цвет, залитая иконка, `aria-pressed="true"`. Числа — по языку (`formatNumber`, «1 000»). Ряд —
   `role="group"` с подписью «Реакции».
5. **Шов для набора реакций.** Виды перечислены в `frontend/api/reactions.ts` (`reactionKinds`) и в
   `ReactionKind` модуля; E02-12/E10-02 добавят туда виды, иконки и подписи, а API чтения — список видов со
   счётчиками вместо `{count, liked}`. Компонент, сортировка и событие уже принимают несколько видов.

## Последствия

- Счётчики под постом и комментариями меняются без перезагрузки у всех вошедших читателей страницы.
- API чтения и записи не изменились (`{count, liked}`); событие не входит в OpenAPI, его форма описана здесь и в
  `ReactionEvents`.
- Счётчик в карточке ленты живым не стал: лента на тему поста не подписывается.
- Перечитывание счётчиков после переподключения канала не сделано: событий, пропущенных в обрыве, страница не
  узнает до следующего открытия.
