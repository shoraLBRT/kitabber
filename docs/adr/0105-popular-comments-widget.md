# ADR-0105. Виджет «Популярные комментарии»: лучшие нативные комментарии за сутки, общий кэш на минуту

- Статус: предложено
- Дата: 2026-11-27
- Задачи: E08-12 (#101); опирается на [ADR-0081](0081-post-and-comment-rating.md) (рейтинг комментария),
  [ADR-0101](0101-reaction-choice.md) (вес реакций), [ADR-0062](0062-feed-best-comment.md) (лучший комментарий карточки,
  обрезка текста), [ADR-0080](0080-feed-cache.md) (кэш лент), [ADR-0091](0091-black-list.md) (чёрный список),
  [ADR-0048](0048-comment-tree-and-api.md) (модуль Comments и `IPostDirectory`)

## Контекст

FR-FEED: в правой колонке десктопа — виджет «Популярные комментарии». Критерии E08-12: виджет показывает комментарии с
наибольшим рейтингом за сутки, гостевые комментарии из Telegram в него не попадают, виджет кэшируется. До задачи
`ShellAside` показывал в виджете пустое состояние. Нужно решить, что такое «за сутки», откуда берутся данные и как
устроен кэш, если часть ответа (заблокированные авторы) у каждого читателя своя.

## Решение

1. **«За сутки» — комментарии, написанные за последние 24 часа**, а рейтинг — полный рейтинг комментария
   (`IReactionRatings`, сумма реакций по весам, ADR-0081). Реакции по времени не учитываются: модуль Reactions хранит
   готовый рейтинг, а не историю, и за сутки после написания почти все реакции и так приходятся на этот день. Окно
   скользящее (`PopularComments.Window`), время — через `TimeProvider`.
2. **В виджет входят только показанные нативные комментарии под опубликованными постами с рейтингом выше нуля.**
   Гостевой комментарий (`kind = Guest`, FR-TG-6) отсекается запросом, даже если для него есть рейтинг. Комментарий
   без реакций не попадает: виджет — о том, что понравилось, а не о новом. Порядок — рейтинг по убыванию, при равенстве
   более ранний, затем меньший id (порядок полный).
3. **Эндпоинт — в модуле Comments:** `GET /api/v1/comments/popular?limit=1..10` (по умолчанию 5). Модуль читает свои
   комментарии, о постах спрашивает `IPostDirectory.PublishedHeadlinesAsync` (новый метод контракта: опубликованные
   посты из списка одним запросом — id, блог, заголовок, слаг), о рейтингах — `IReactionRatings`. Чужие таблицы он не
   читает. Ответ: id комментария, id поста и его блога, заголовок и слаг поста, автор (`account_id`), начало текста
   (`BestComments.Excerpt`, как у лучшего комментария карточки), рейтинг, время.
4. **Кэш — один выбор на всех, на минуту** (`PopularCommentsCache`, ключ `comments:popular` в Redis, срок
   `Lifetime` = 1 минута, проверяется по `TimeProvider`). Кэшируется запас из 30 комментариев (`Stock`), а уже после
   кэша для вошедшего убираются авторы, которых он заблокировал (`IBlockList`, ADR-0091), и комментарии, вышедшие из
   окна суток, — затем берётся `limit`. Запас больше `MaxLimit`, чтобы блокировки не опустошали виджет. Сброса по
   событиям нет: реакция или новый комментарий появятся в виджете не позже чем через минуту. Кэш только ускоряет: если
   Redis не отвечает, выбор читается из базы.
5. **Индекс `ix_comments_day`** — частичный по `created_at` для `kind = 'Native' AND deleted_at IS NULL`: чтение окна
   суток идёт по нему, а не по всей таблице.
6. **Клиент.** Раскладка `default` кладёт в `ShellAside` список `PopularCommentList`: аватар и имя блога автора
   (профили — `loadAuthors`, как в дереве комментариев), до трёх строк текста и заголовок поста; весь пункт — ссылка на
   комментарий `/u/<blogId>/<id-slug>#comment-<id>` (страница поста ведёт к каноническому адресу, ADR-0041). Данные
   берутся в браузере через `/bff/popular-comments` (BFF передаёт токен, чтобы сервер убрал заблокированных) и
   только пока правая колонка на экране (`asideQuery`, от 1240 px): телефон и узкое окно виджет не запрашивают.
   Перечитывается при входе и выходе. Состояния — общие `ShellWidget`: загрузка, ошибка с «Повторить», пусто.

## Последствия

- Виджет запаздывает не больше чем на минуту; на нагрузку от него влияет только число промахов кэша (раз в минуту).
- Если понадобится «рейтинг, набранный за сутки» (реакции за день, а не комментарии дня), модулю Reactions нужно будет
  хранить время реакций в рейтинге или отдавать сумму за окно — это отдельное решение.
- «Интересные блоги» в правой колонке по-прежнему пусты: это отдельная задача.
