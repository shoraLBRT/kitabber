# ADR-0010. Образы в GHCR, стенд на Docker Compose, выкладка тегом по SSH, откат — прежний тег

- Статус: предложено (задача E01-03, #10); хостинг не выбран, владелец может пересмотреть в PR
- Задачи: E01-03; опирается на [ADR-0001](0001-stack.md), [ADR-0004](0004-database-migrations.md),
  [ADR-0007](0007-configuration-and-secrets.md). Инструкция — [DEPLOY.md](../DEPLOY.md)

## Контекст

Нужна автовыкладка на stage, ручная на production и откат, а хостинга ещё нет. Решение не должно зависеть от
поставщика: подойти должен любой сервер с Docker, а CI — оставаться зелёным без ключей владельца.

## Решение

1. **Пять образов** (`api`, `workers`, `migrator`, `frontend`, `admin`), список — только в `scripts/images.ps1`.
   Мигратор — отдельный образ: API при старте не мигрирует (ADR-0004). Базовые образы закреплены по дайджесту.
2. **Реестр — GHCR**, публикация через `GITHUB_TOKEN` (`packages: write`). Неизменяемый тег выкладки —
   `sha-<7 знаков>`; `latest` и номера версий release-please — только для людей.
3. **Стенд — Docker Compose** (`deploy/compose.stage.yaml`) с PostgreSQL, Redis, RabbitMQ и Caddy (TLS от Let's
   Encrypt, сайт и админка на двух адресах). Управляемые сервисы хостинга подставляются заменой строк подключения.
4. **Выкладка — `scripts/deploy.ps1`**, Docker сервера — через `DOCKER_HOST=ssh://…` с раннера GitHub; на сервер
   ничего не копируется, кроме образов. Порядок: мигратор новой версии, затем замена контейнеров с ожиданием
   healthcheck. Упавшая миграция останавливает выкладку, работает прежняя версия.
5. **Откат — выкладка прежнего тега.** Миграции идут только вперёд и совместимы с предыдущей версией кода
   (сначала добавляем, удаляем следующим релизом). Откат схемы — только явно, мигратором новой версии
   (`rollback <схема>`) до выкладки старого тега.
6. **Секреты стенда** — секреты окружения GitHub Actions (`stage`, `production`), выкладка пишет их в env-файл
   на раннере (рекомендация ADR-0007). Production защищается обязательным подтверждением окружения.
7. **Автовыкладка на stage включается переменной репозитория `DEPLOY_STAGE=true`**; без неё задание
   пропускается.
8. **Проверка без сервера**: смоук `scripts/deploy-test.ps1 -Smoke` в отдельном задании `images / build` на
   каждом PR выкладывает, обновляет, роняет миграцию и откатывает стенд на Docker раннера; статические проверки —
   в `scripts/verify.ps1`.

## Последствия

- Любой сервер с Docker Engine и SSH годится; Kubernetes и PaaS не нужны, но и не исключены: образы те же.
- Сборка образов (минуты) не входит в 10 минут `ci / verify`; её проверяет отдельное задание, которое владелец
  может сделать обязательным.
- Простой при выкладке — секунды на замену контейнеров; для нулевого простоя понадобится второй экземпляр API за
  Caddy, это отдельная задача, когда появится нагрузка.
- Резервные копии баз стендов этим решением не покрыты — это E17-16 (#249).
