# ADR-0046. Публикация поста: проверки, выбор темы, поток из редактора

- Статус: предложено (22 ноября 2026), задача E05-09 (#49); действует, пока владелец не решит иначе
- Требования: [spec.md](../spec.md#fr-editor-редактор) (FR-EDITOR: тема или «без темы», заголовок необязателен,
  валидация — пустой пост, длина заголовка, размер поста и блока), [ui/editor.md](../ui/editor.md)
- Связанные решения: [ADR-0018](0018-openid-connect-provider.md) (токен доступа только на сервере сайта),
  [ADR-0023](0023-block-schemas-and-html-cleaning.md) (схемы блоков и очистка HTML), [ADR-0029](0029-post-model-and-api.md) (черновик виден
  только автору), [ADR-0041](0041-post-address-and-slug.md) (адрес поста)

## Контекст

ТЗ называет проверки перед публикацией, но не даёт чисел и не говорит, где они живут. Модель поста (E07-01, #48)
уже умеет черновик; нужен переход «черновик → опубликован», список тем для выбора и поток в редакторе. Черновики с
автосохранением — отдельная задача, поэтому сохранять черновик нельзя заставлять проходить проверки: иначе текст
теряется на лимите.

## Решение

1. **Проверки — на сервере, при публикации.** `POST /api/v1/posts/{id}/publish` (только автор, нужна подтверждённая
   почта) прогоняет `PostChecks` (модуль Posts) и отвечает `400` с ошибками по полям ([ADR-0006](0006-rest-api-conventions.md)): `title`, `body`,
   `body.blocks[i]`. Сохранение черновика (`POST`/`PUT /posts`) их не прогоняет. Правка уже опубликованного поста
   проходит те же проверки, чтобы опубликованный пост всегда оставался публикуемым. Повторная публикация
   опубликованного поста ничего не меняет и отвечает `200`.
2. **Лимиты.** Заголовок — не длиннее **120** символов после обрезки пробелов (UTF-16, как `string.Length`); блок —
   не больше **64 КБ** своего JSON в UTF-8; весь документ — не больше **512 КБ**. Числа — константы `PostChecks`;
   клиент повторяет только длину заголовка (`frontend/editor/publish.ts`).
3. **Пустой пост** — документ, в котором ни один блок не показывает читателю текст. Это знает схема блока: поле
   говорит `HasContent` (текстовое поле — если после снятия тегов и сущностей остаётся что-то кроме пробелов,
   неразрывных и нулевой ширины; настройки вроде уровня заголовка — никогда). Валидатор документа отдаёт это как
   `IBlockDocumentValidator.HasContent`, поэтому модуль Posts не знает устройства блоков. Разделитель один — пустой
   пост. Клиент повторяет правило (`isEmptyDocument`) и держит кнопку «Опубликовать» выключенной.
4. **Темы.** `GET /api/v1/topics` (модуль Blogs, открыт всем) — все темы с именем и адресом по алфавиту, не больше
   500; каталог с поиском — E11-02 (#78). «Без темы» — это `blogId: null`: пост уходит в личный блог автора. Темы
   создаёт администрация (E11-01, #76); до её инструментов — демо-данные (`TopicsDemoData`) и тесты.
5. **Поток в редакторе.** Браузер шлёт заголовок, тему и документ на сервер сайта (`/bff/publish`), тот сохраняет
   черновик и публикует его токеном человека (ADR-0018) и возвращает итог редактора: опубликован с каноническим
   адресом, ошибки по полям, нужна подтверждённая почта, нужен вход, сбой. Черновик неудачной попытки возвращается
   (`draftId`), повтор пишет в него, а не создаёт второй. Опубликованный пост открывается на своей странице.

## Последствия

- Лимиты меняются в одном месте на сервере и в одной константе клиента; тесты обеих сторон ссылаются на них.
- Новый тип блока должен сказать, какие его поля — содержимое, иначе пост из одного такого блока считается пустым.
- Гость, нажавший «Опубликовать», получает окно входа; текст через вход не переносится, пока нет черновиков с
  автосохранением.
- Обложка и «кто может комментировать» из параметров публикации — свои задачи; здесь их нет.
